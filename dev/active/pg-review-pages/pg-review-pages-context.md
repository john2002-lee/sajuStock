## 구현하면서 계획과 달라진 것

1. **무료 이벤트를 남기지 않고 지웠다.** 계획은 "기간만 지나가게 두고 함수는
   남긴다" 였다. 그런데 paywall 게이트가 생기면서, 다음에 그 상수를 되살리면
   무료 경로가 `/saju/report` 로 보내고 그 경로는 402 로 거절된다 — **되살리는
   순간 고장 나는 덫**이 된다. 다음 행사는 쿠폰이나 서버 주도 방식이라야 한다.

2. **결제 설정 조회 실패가 유료 상품을 무료로 열어 주고 있었다.** 계획에 없던
   발견이다. `TeaserScreen` 이 실패를 `null` 로 두고 무료 버튼을 그렸기 때문에,
   개발자 도구로 요청 하나만 막으면 누구나 재현할 수 있었다. `PaymentState`
   셋으로 갈랐다.

3. **청약철회 동의를 결제 화면에 넣었다.** 전자상거래법 제17조는 디지털
   콘텐츠의 철회 제한을 약관에 적는 것만으로 인정하지 않는다 — **사는 순간에**
   동의를 받아야 한다. 동의 전에는 결제 버튼이 눌리지 않는다.

4. **환경변수 이름을 ASCII 로.** `NEXT_PUBLIC_BIZ_상호` 는 Vercel·dotenv·셸이
   받지 못한다. 한글은 화면 라벨로만 쓰고 `businessRows()` 가 순서와 라벨을
   명시적으로 든다(`Object.entries` 를 버렸다).

5. **가격을 프런트 상수로 두었다**(`REPORT_PRICE`). 공개 소개 페이지가 결제
   API 에 기대면 Cloud Run 콜드 스타트 동안 상점이 오류 화면이 된다. 대신
   백엔드에 `saju_report_price == 1000` 테스트를 걸어 복사본이 어긋나면 깨지게 했다.

6. **푸터 사업자 정보는 실제 값일 때만 그린다.** 임시 등록번호를 전 화면에
   뿌리는 것은 없는 것보다 나쁘다. 법적 문서 안에서는 "아직 등록 전" 고지와
   함께 나오므로 그쪽은 그대로 둔다.

## 결제 화면 문구 — 법률 검토 결과 (2026-09-22)

소유자 요청은 "고지표를 약관으로 옮기고 포괄 동의 한 줄로" 였다. 법률 검토 2건 +
반박 검증 4건을 돌렸고, **반박 4건 전부 핵심 결론을 뒤집지 못했다.**

**결정적 조문: 전자상거래법 제17조 제2항 단서.** 디지털 콘텐츠의 환불 제한은
구매자가 동의해서 서는 것이 아니라, 파는 쪽이 제6항 조치(= 철회 불가 사실을
"소비자가 쉽게 알 수 있는 곳에 명확하게 표시")를 했을 때만 선다. 표시를 약관 링크
뒤로 넘기면 조치 미이행 → 단서 발동 → **리포트를 끝까지 읽은 사람도 7일 안에 전액
환불을 요구할 수 있고 거절할 근거가 없다.** 약관에 뭐라 적어도 제35조로 무효.

요건은 **위치**이지 형식이 아니다 → 표를 카피로 바꾸는 리디자인은 가능. 값 자체를
옮기는 것이 불가.

화면에 남긴 다섯: 상품명(토스 `orderName` 과 동일) · 가격+부가세 · 제공 시점 ·
열람 기간과 링크 분실 안내 · 환불 제한 사실.

**시험 사용 조치는 이미 이행 중이다** — 무료 티저가 구매자 **본인의** 여덟 글자를
보여 주므로 시행령 제21조의2 제1호 '일부 이용의 허용'. 검토자 1명이 "미리보기가
없으면" 을 걱정했으나 검증에서 사실오인으로 정정됐다. 새로 만들 것 없음.

**개인정보는 동의로 묶지 않는다.** 개인정보보호법 제22조 제1항(동의 사항을 구분해
각각)에 걸리고, 애초에 생년월일시는 제15조 제1항 제4호(계약 이행)로 동의 없이
처리한다 — 동의 기반으로 바꾸면 근거만 약해진다. 처리방침은 링크로 알리기만.

**"청약철회" 라는 말은 화면에서 쓰지 않는다**(소유자 지시). 기준 시점도 평문 쪽이
정확하다 — 제5호는 "제공이 개시된 경우" 이지 "생성이 시작된 경우" 가 아니다.
법령 용어는 약관 제6조와 `/refund` 가 든다.

### 남은 한계
- 체크박스가 `useState` 라 서버에 기록되지 않는다 → "동의한 적 없다" 다툼의 증거가
  못 된다. 법 요건은 동의가 아니라 **표시**이고 그것은 렌더로 이행되므로 지금은
  받아들일 만하다. 증거까지 남기려면 주문에 함께 저장해야 한다.
- 검증자들이 공통으로 지적한 **최대 심사 반려 요인은 문구가 아니라 판매자 신원
  부재** — `NEXT_PUBLIC_BIZ_*` 가 비어 있어 푸터에 사업자 정보가 아예 없다.
  통신판매업 신고 → 실값 주입이 문구 작업보다 선행한다.
