## 4. 결제 경로 (심사자가 그대로 따라갈 수 있는 순서)

회원가입이 없으므로 **테스트 계정이 필요 없다.**

1. https://www.aiot21.com 접속 (첫 화면이 사주 입력 화면)
2. 생년월일·시각·출생지·성별 입력 → **"무료로 사주팔자 보기"**
   (아무 날짜나 넣어도 된다. 예: 1990년 5월 15일 9시 30분, 서울, 남성)
3. 무료 결과 화면(`/saju/teaser`) — 여덟 글자와 판정이 보이고, 아래 구매 카드에
   상품명·한 줄 소개·가격(부가세 포함)·제공 시점·보관 기간·환불 제한이 표시된다
   (구성 전문은 이용약관 제2조와 소개 페이지에 있다)
4. 환불 제한 안내 체크박스에 체크 → **결제 버튼** → 토스페이먼츠 결제창
5. 결제 승인 → `/saju/pay/success` → 리포트 생성 후 열람

결제 실패·취소 시 `/saju/pay/fail` 로 돌아오며 결제되지 않는다.

## 6. 환불 정책 요약

- 리포트 생성 시작 전: 전액 환불
- 리포트가 정상 제공된 뒤: 디지털 콘텐츠 제공 완료로 청약철회 제한
  (전자상거래법 제17조 제2항 제5호). 결제 **화면에서** 제한 사실을 표시하고 체크를 받는다
- 생성 실패·결제 결과 미확인·중복 결제: 담당자 확인 후 영업일 1일 이내 전액 환불
- 미성년자가 법정대리인 동의 없이 결제: 리포트 생성 여부와 관계없이 취소·환불 (약관 제5조의2, 제6조 단서)
- 접수: cs@aiot21.com

## 7. 콘텐츠 표현 원칙

- 리포트는 **참고용 해설**이며 결과를 보장하지 않는다고 약관 제2조·제8조와 푸터에 고지
- 사이트 문구에 "정확하게" 같은 정확성 주장을 쓰지 않는다
- 리포트는 AI 가 쓰지만, 출력은 사용자에게 가기 전에 **서버 검증기**를 거친다 —
  불행한 사건의 단정 예언("반드시 ~를 당한다" 류), 질병 진단·치료 지시, 굿·부적 권유,
  소송 결과 단정, 투자 수익 단정이 걸리면 다시 쓰게 하고, 그래도 안 되면 계산 결과만
  담은 간이 리포트로 대체한다
- 의료·법률·투자 판단을 대신하지 않는다고 고지
- 공포·불안을 자극해 추가 결제를 유도하는 구조가 없다 (상품이 1종이고 추가 결제 경로가 없다)

## 8. 결제 연동 상태

- 결제창형 연동 완료. 현재 **테스트 키**로 운영 중이며, 사이트에 "결제는 테스트 용도입니다" 고지가 뜬다
- 라이브 키는 통신판매업 신고번호를 사이트에 넣은 뒤에 적용한다
- 라이브 키를 넣으면 고지는 자동으로 사라진다 (`NEXT_PUBLIC_TOSS_CLIENT_KEY` 의 `test_` 접두사에서 파생)
- 결제 금액은 서버가 확정하고 승인 시 서버가 다시 대조한다
