# 금융·주식 분석 서비스 프론트엔드 및 사업 기획

> 최초 작성: 2026-07-29  
> 기준 코드: `back/finance.py`, `back/main.py`, `front2/`  
> 문서 목적: 프론트엔드 기획, 개발 착수, 사업성 검증 내용을 한곳에 누적 관리한다.

---

## 1. 문서 사용 방법

이 문서는 다음 세 가지 용도로 사용한다.

1. 백엔드가 제공하는 금융 기능과 API 계약을 파악한다.
2. 프론트엔드 MVP의 화면, 상태, 개발 순서를 정한다.
3. 문서 하단의 프롬프트를 Claude에 입력해 기술 및 사업 기획을 구체화한다.

기능이나 정책이 바뀌면 문서 하단의 변경 이력에 날짜와 변경 내용을 추가한다.

---

## 2. 프로젝트 현황 요약

현재 프로젝트는 완전한 신규 프로젝트가 아니다.

- `back/finance.py`
  - 시장 데이터 조회
  - 국내 상장사 검색
  - 주가 이력 및 기술적 지표 계산
  - 뉴스 및 애널리스트 리포트 수집
  - 멀티 에이전트 기반 AI 투자 판단
- `back/main.py`
  - FastAPI 앱에 금융 라우터 연결
  - 인증된 대화방 단위의 투자 판단 API 제공
- `front2/`
  - Next.js 기반 프론트엔드
  - 시장 현황, 종목 검색, 주가 차트, 투자 판단 관련 타입과 컴포넌트가 일부 구현됨

따라서 첫 작업은 전체 재개발보다 아래 순서가 적합하다.

1. 현재 구현 범위 점검
2. 백엔드 응답과 프론트 타입 동기화
3. 빠진 화면과 상태 보완
4. 사용자 검증을 위한 MVP 배포
5. 실제 사용 지표로 사업성 검증

---

## 3. 제품 한 줄 정의

개인 투자자가 여러 금융 사이트를 오가지 않고도 시장 현황, 종목 차트, 기술적 신호, 뉴스와 AI 분석을 한 화면에서 확인할 수 있는 주식 리서치 보조 서비스.

AI의 역할은 수익을 보장하거나 매매를 지시하는 것이 아니라, 분산된 정보를 정리하고 판단 근거를 이해하기 쉽게 보여주는 것이다.

## 4. 주요 사용자 가설

### 4.1 우선 대상

- 국내 주식 투자를 시작한 초보 투자자
- 차트와 뉴스를 함께 보고 싶지만 전문 지표 해석이 어려운 사용자
- 종목 조사 시간을 줄이고 싶은 직장인 투자자
- 여러 자료를 비교한 뒤 최종 판단은 직접 내리고 싶은 사용자

### 4.2 사용자가 겪는 문제

- 종목 가격, 차트, 뉴스, 리포트가 여러 서비스에 분산되어 있다.
- SMA, 볼린저밴드, 골든크로스 같은 지표를 이해하기 어렵다.
- 뉴스가 주가에 어떤 위험 또는 기회를 주는지 판단하기 어렵다.
- 생성형 AI 답변만으로는 근거와 신뢰도를 확인하기 어렵다.

### 4.3 제안 가치

- 시장부터 개별 종목까지 한 번에 탐색
- 기술적 지표를 원본 수치와 쉬운 설명으로 함께 제공
- AI 에이전트별 관점을 분리해 판단 근거를 투명하게 제공
- 최종 판단과 함께 매수 조건, 위험 요소, 신뢰도를 제공

---

## 5. 핵심 사용자 흐름

```text
시장 현황 확인
  → 관심 종목 검색
  → 가격 및 기술적 지표 확인
  → 뉴스와 리포트 확인
  → AI 분석 요청
  → BUY / WATCH / AVOID 및 근거 확인
  → 사용자가 직접 투자 여부 판단
```

## 6. 백엔드 기능 및 주요 메서드

### 6.1 종목 코드와 검색어 정규화

주요 메서드:

- `normalize_stock_candidates`
  - `삼성전자`, `005930`, `005930.KS`, `AAPL` 같은 입력을 yfinance 조회 후보로 변환
- `get_common_stock_name`
  - 자주 사용하는 종목 입력을 한글 표시명으로 변환
- `normalize_stock_code`
  - 종목 코드에서 숫자 6자리를 추출
- `get_initial_consonants`
  - 한글 종목명을 초성 문자열로 변환
- `krx_symbol_to_yfinance`
  - KOSPI는 `.KS`, KOSDAQ/KONEX는 `.KQ` 형식으로 변환

### 6.2 상장사 목록 구축

주요 메서드:

- `fetch_krx_listed_companies`
  - KRX에서 전체 상장사 CSV 수집
- `fetch_kind_listed_companies`
  - KRX 조회 실패 시 KIND 상장사 목록 사용
- `fallback_listed_companies`
  - 외부 목록 수집 실패 시 코드 내부 기본 종목 사용
- `ensure_listed_companies`
  - DB의 상장사 수가 100개 미만이면 목록 수집 및 저장

첫 자동완성 호출에서는 상장사 목록을 수집할 수 있어 응답이 평소보다 늦을 수 있다.

### 6.3 주가·뉴스·리포트

주요 메서드:

- `fetch_stock_history_from_yfinance`
  - OHLCV, 이동평균선, 볼린저밴드, 교차 신호 생성
- `fetch_stock_news`
  - 종목 뉴스 최대 3건 수집
- `fetch_analyst_reports`
  - 등급 변경, 목표가, 추천 요약 등 최대 3건 수집
- `fetch_market_overview_from_yfinance`
  - 시장 카테고리별 현재값, 변동률, 차트 데이터 생성

### 6.4 투자 지표와 AI 판단

주요 메서드:

- `build_stock_metrics`
  - 최근 가격, 등락률, 20일·60일 수익률, 추세, 거래량 배율 등을 계산
- `invoke_stock_agent`
  - 저널리스트, 경제학자, 애널리스트 역할의 의견 생성
- `invoke_decision_agent`
  - 하위 에이전트 의견을 종합해 최종 판단 생성
- `fallback_decision`
  - LLM 호출 실패 시 규칙 기반 판단 생성
- `generate_stock_advice`
  - 주가 조회부터 최종 판단까지 전체 흐름 실행

AI 분석은 주가와 외부 콘텐츠 조회 및 여러 번의 LLM 호출을 포함하므로 일반 주가 조회보다 오래 걸릴 수 있다.

## 7. API 명세

금융 라우터에는 별도 prefix가 없으므로 다음 경로를 그대로 호출한다.

### 7.1 종목 자동완성

```http
GET /stocks/suggestions?query=삼성&limit=5
```

파라미터:

| 이름 | 필수 | 기본값 | 제한 | 설명 |
|---|---:|---:|---:|---|
| `query` | 예 | 없음 | 1자 이상 | 종목명, 코드 또는 초성 |
| `limit` | 아니요 | 5 | 1~10 | 최대 결과 수 |

응답:

```json
[
  {
    "symbol": "005930.KS",
    "name": "삼성전자",
    "market": "KOSPI",
    "initial_consonants": "ㅅㅅㅈㅈ"
  }
]
```

검색 우선순위:

1. 종목 코드 시작 일치
2. 종목명 시작 일치
3. 초성 시작 일치
4. 종목명 부분 일치
5. 초성 부분 일치

### 7.2 주가 이력

```http
GET /stocks/history?symbol=005930.KS&timeframe=day&limit=504
```

날짜 직접 지정:

```http
GET /stocks/history?symbol=AAPL&timeframe=day&start_date=2026-01-01&end_date=2026-07-29&limit=5000
```

파라미터:

| 이름 | 필수 | 기본값 | 제한 또는 값 |
|---|---:|---:|---|
| `symbol` | 예 | 없음 | 1자 이상 |
| `timeframe` | 아니요 | `day` | `day`, `week`, `month` |
| `period` | 아니요 | timeframe별 기본값 | `5d`, `1mo`, `3mo`, `6mo`, `1y`, `2y`, `5y`, `ytd`, `max` |
| `limit` | 아니요 | 504 | 1~5000 |
| `start_date` | 아니요 | 없음 | `YYYY-MM-DD` |
| `end_date` | 아니요 | 없음 | `YYYY-MM-DD` |

조회 단위:

| timeframe | 실제 interval | 기본 period |
|---|---|---|
| `day` | `1d` | `2y` |
| `week` | `1wk` | `5y` |
| `month` | `1mo` | `max` |

`start_date` 또는 `end_date`가 하나라도 전달되면 `period`는 사용하지 않고 응답의 `period`가 `custom`이 된다. `end_date`는 해당 날짜까지 포함된다.

응답 핵심 구조:

```json
{
  "name": "삼성전자",
  "symbol": "005930.KS",
  "query": "삼성전자",
  "timeframe": "day",
  "period": "2y",
  "interval": "1d",
  "start_date": null,
  "end_date": null,
  "rows": [
    {
      "name": "삼성전자",
      "symbol": "005930.KS",
      "date": "2026-07-29",
      "open": 100,
      "high": 110,
      "low": 98,
      "close": 107,
      "volume": 1000000,
      "sma5": 103.4,
      "sma20": 99.8,
      "bb_upper": 112.5,
      "bb_lower": 87.1,
      "cross_signal": "golden"
    }
  ],
  "news": [],
  "reports": []
}
```

`cross_signal` 값:

- `golden`
- `dead`
- `null`

초기 행은 계산에 필요한 데이터가 부족해 SMA와 볼린저밴드가 `null`일 수 있다.

### 7.3 시장 현황

```http
GET /markets/overview?category=index
```

카테고리:

| 값 | 화면명 | 주요 데이터 |
|---|---|---|
| `index` | 지수 | 코스피, 코스피200, S&P 500, 나스닥100 등 |
| `forex` | 외환 | 달러/원, 유로/달러, 엔/원 등 |
| `commodity` | 원자재 | 금, 은, WTI, 천연가스, 구리 등 |
| `stock` | 해외주식 | AAPL, TSLA, BABA, KO 등 |

응답:

```json
{
  "category": "index",
  "label": "지수",
  "rows": [
    {
      "name": "코스피지수",
      "symbol": "^KS11",
      "value": 3120.5,
      "change": 15.2,
      "change_percent": 0.49,
      "tone": "up",
      "highlight": true,
      "chart_points": [],
      "chart_labels": []
    }
  ],
  "chart_points": [],
  "chart_labels": [],
  "updated_at": "2026-07-29T10:30:00"
}
```

### 7.4 AI 투자 판단

```http
POST /stocks/advice
Content-Type: application/json
```

```json
{
  "symbol": "005930.KS"
}
```

`symbol`은 1~80자이다.

응답 핵심 구조:

```json
{
  "stock": {
    "name": "삼성전자",
    "symbol": "005930.KS",
    "query": "005930.KS"
  },
  "stock_data": {},
  "metrics": {
    "latest_date": "2026-07-29",
    "latest_close": 107,
    "day_change": 2,
    "day_change_pct": 1.9,
    "return_20d_pct": 8.2,
    "return_60d_pct": 12.5,
    "sma5": 103.4,
    "sma20": 99.8,
    "trend": "상승 우위",
    "bollinger_position": "중립",
    "volume_ratio_20d": 1.32,
    "recent_cross_signal": "golden",
    "recent_cross_date": "2026-07-21"
  },
  "agents": [
    {
      "agent": "AI 애널리스트",
      "status": "done",
      "summary": "분석 내용"
    }
  ],
  "verdict": "BUY",
  "decision_label": "매수 가능",
  "confidence": 76,
  "answer": "최종 판단",
  "buy_conditions": [],
  "risk_notes": [],
  "updated_at": "2026-07-29T10:30:00"
}
```

판단값:

| 값 | 화면 문구 | 권장 표현 |
|---|---|---|
| `BUY` | 매수 가능 | 녹색 |
| `WATCH` | 관망 | 노랑 또는 주황 |
| `AVOID` | 매수 보류 | 빨강 |

`agents[].status`가 `fallback`이면 `error`가 포함될 수 있다. 사용자에게 내부 오류 원문을 그대로 보여주기보다 “일부 AI 분석을 기본 지표 분석으로 대체했습니다”처럼 정제해 안내하는 것이 적절하다.

### 7.5 인증된 대화방 투자 판단

현재 프론트는 다음 API도 사용한다.

```http
POST /conversations/{conversationId}/stock-advice
Authorization: Bearer ...
```

요청 본문과 응답은 `/stocks/advice`와 동일하다.

차이점:

- 로그인이 필요하다.
- 대화방 ID를 사용한다.
- 새 대화의 제목을 요청한 종목명으로 변경한다.

## 8. 프론트엔드 화면 요구사항

### 8.1 시장 현황 영역

- 지수, 외환, 원자재, 주식 탭
- 대표 지표 메인 차트
- 항목별 현재값, 변동값, 변동률
- 항목별 미니 차트
- 상승·하락 색상 및 아이콘
- 마지막 갱신 시각
- 수동 새로고침
- 필요하면 일정 주기의 polling

### 8.2 종목 검색

- 종목명, 코드, 초성 입력
- 250~400ms debounce 자동완성
- 최대 5건 우선 노출
- 결과에 종목명, 코드, 시장 표시
- 키보드 위·아래 이동
- Enter 선택
- ESC 닫기
- 검색 결과 없음 상태
- 최초 상장사 목록 구축 중 로딩 상태

### 8.3 종목 요약

- 종목명 및 코드
- 최근 종가
- 일간 변동값과 변동률
- 조회 기준일
- 현재 추세
- 최근 교차 신호

### 8.4 차트와 테이블

- 일봉, 주봉, 월봉 선택
- 기간 프리셋
- 시작일과 종료일 직접 선택
- 캔들 차트
- SMA5/SMA20 표시 토글
- 볼린저밴드 표시 토글
- 골든크로스·데드크로스 마커
- 거래량 차트
- OHLCV 및 보조지표 테이블
- 모바일에서 차트 확대 모달 또는 전체 화면

### 8.5 관련 콘텐츠

- 뉴스 목록
- 애널리스트 리포트 목록
- 제목, 발행처, 날짜, 요약
- 새 창으로 원문 열기
- 썸네일이 없을 때 기본 이미지
- 결과가 없을 때 빈 상태

### 8.6 AI 투자 판단

- 사용자가 명시적으로 누르는 분석 시작 버튼
- 주가 조회와 분리된 장기 로딩 상태
- `BUY`, `WATCH`, `AVOID` 판단 배지
- 신뢰도 0~100 게이지
- 최종 답변
- 에이전트별 분석 의견
- 매수 검토 조건
- 위험 요소
- 분석 갱신 시각
- 일부 에이전트가 fallback인 경우 상태 안내
- “투자 손익을 보장하지 않는 참고 정보” 고지

## 9. 상태 및 오류 처리

필수 상태:

- 최초 진입
- 종목 미선택
- 자동완성 로딩
- 검색 결과 없음
- 주가 조회 로딩
- AI 분석 장기 로딩
- 데이터 일부만 존재
- 네트워크 오류
- 재시도
- 잘못된 날짜 범위
- 빈 뉴스 또는 리포트
- null 가격 및 지표

백엔드 주요 오류:

| HTTP 상태 | 발생 조건 |
|---|---|
| `400` | 잘못된 timeframe, period, category 또는 날짜 순서 |
| `404` | 종목 주가를 찾을 수 없음 |
| `422` | 필수 입력 누락 또는 길이·범위 오류 |
| `503` | yfinance 미설치 또는 시장 데이터 조회 실패 |

FastAPI의 오류 응답은 보통 다음 형태다.

```json
{
  "detail": "오류 내용"
}
```

## 12. 사업성 검증 시작안

### 12.1 먼저 검증할 가설

1. 사용자는 차트와 뉴스가 한 화면에 있는 것만으로도 시간을 절약한다고 느낀다.
2. 사용자는 단일 AI 답변보다 역할별 분석 근거를 더 신뢰한다.
3. 사용자는 `BUY/WATCH/AVOID`보다 매수 조건과 위험 요소에 더 높은 가치를 느낀다.
4. 반복 사용자는 관심 종목 저장, 알림, 분석 이력에 비용을 낼 의향이 있다.

### 12.2 초기 검증 방법

- 타깃 사용자 5~10명 문제 인터뷰
- 클릭 가능한 화면 또는 현재 MVP로 사용성 테스트
- 랜딩 페이지에서 대기자 등록 측정
- 무료 사용자에게 가짜 결제 버튼이 아닌 가격 선호 설문 실시
- 동일 종목에 대해 기존 포털 사용 시간과 서비스 사용 시간 비교
- 분석 결과의 유용성, 이해도, 신뢰도를 각각 측정

### 12.3 핵심 측정 지표

- 방문 후 첫 종목 조회 완료율
- 첫 가치 도달 시간
- 검색 후 AI 분석 실행률
- AI 분석 완료율
- 1일 및 7일 재방문율
- 사용자당 주간 종목 조회 수
- 관심 종목 저장률
- 분석 결과 도움됨 응답률
- 유료 기능 관심도

### 12.4 가능한 수익 모델

무료:

- 기본 시장 현황
- 제한된 종목 조회
- 기본 차트와 뉴스
- 일일 제한된 AI 분석

유료 구독:

- AI 분석 횟수 확대
- 관심 종목과 포트폴리오
- 가격·신호·뉴스 알림
- 분석 결과 비교 및 이력
- 고급 지표와 리포트

B2B 가능성:

- 투자 교육 서비스용 리서치 도구
- 커뮤니티나 콘텐츠 플랫폼에 종목 분석 위젯 제공
- 금융 데이터 기반 상담 보조 화면 제공

### 12.5 주요 사업 위험

- yfinance 및 외부 뉴스 데이터의 안정성과 상업적 이용 조건
- 실시간성이 필요한 사용자 기대와 지연 데이터 간 차이
- 투자 자문으로 오해될 수 있는 표현
- AI 결과의 부정확성 및 과신
- 유료 금융 데이터 라이선스 비용
- 해외 서비스와 국내 증권사 앱의 강한 경쟁
- LLM 호출 비용과 분석 응답 시간

사업 검증 단계에서 데이터 출처별 이용약관, 재배포 가능 범위, 지연 시세 표시 의무, 투자자문 관련 규제를 전문가와 확인해야 한다. 문구만으로 법적 위험이 모두 해소되는 것은 아니다.

### 12.6 초기 차별화 방향

단순히 “AI가 종목을 추천한다”는 메시지는 경쟁이 심하고 신뢰 위험이 크다. 다음 방향이 더 적합하다.

- 결론보다 근거가 보이는 AI 리서치
- 기술 지표를 초보자 언어로 설명
- 서로 다른 AI 역할의 의견과 불일치를 투명하게 표시
- 사용자가 직접 설정한 조건에 따른 관찰 목록
- 매수 추천보다 “어떤 조건을 더 확인해야 하는가”를 제공
