# 사주 → 투자 성향 매핑 규칙

>

> 확실히 질문받는 항목이다."* 관련: [통합 기획](saju-integration-plan.md)

## 1. 이 매핑이 주장하는 것과 주장하지 않는 것

**주장하지 않는다: 사주가 주가를 예측한다.**
이 함수의 출력은 종목에 대한 정보가 아니라 **사람에 대한 초안**이다. 사주는 "이 종목이
오를까"에 답하지 않고 "당신은 어떤 투자자인가"에만 답한다 (기획 1절).

**주장한다: 사주 해석은 성향 설문의 대체 입력으로 쓸 만하다.**
증권사 투자성향 설문 20문항은 완주율이 낮다. 생년월일시 네 개로 초안을 만들고 사용자가
세 번 탭해서 고치는 편이, 20문항을 포기하는 것보다 낫다 (기획 3.4).

**이 매핑이 틀려도 제품은 깨지지 않는다.** 세 겹의 안전장치가 있다.

| 겹 | 무엇이 막는가 | 코드 |
|---|---|---|
| ① 사용자 보정 | 초안이 틀리면 사용자가 고친다. 고치는 순간 `source` 가 `user_edited` 가 되어 근거가 사용자 본인에게 넘어간다 | [`ProfileEditor.tsx`](../front/src/features/saju/components/ProfileEditor.tsx) |
| ② 단방향 보정 | 성향은 판단을 **보수적인 쪽으로만** 민다. 적합도가 아무리 높아도 `AVOID` 가 `BUY` 로 올라가지 않는다 | [`domain/verdict.py`](../back/app/domain/verdict.py) |
| ③ 원문 격리 | 사주 원문·오행·십신은 판단 경로에 들어가지 않는다. 판단이 보는 것은 숫자 6개뿐이다 | [`domain/fit.py`](../back/app/domain/fit.py) |

세 겹을 합치면 **"사주 때문에 손해봤다"가 구조적으로 성립하지 않는다** — 사주 경로는
언제나 더 보수적으로만 밀었기 때문이다.

## 2. 출력 계약

```python
class ProfileAxes:
    risk_appetite: int   # 0~100  위험 감수도
    patience: int        # 0~100  보유기간 선호 (낮을수록 단타)
    decisiveness: int    # 0~100  결정 속도 (높을수록 충동적)
    loss_aversion: int   # 0~100  손실 회피 강도
    herd_tendency: int   # 0~100  군중 추종 성향
    saju_summary: str    # 표시 전용 — 판단 계산에 절대 넣지 않는다
```

`saju_summary` 만 문장이고 나머지는 전부 숫자다. 그 문장은 프로파일 화면에만 뜨고
판단 화면에도, 판단 LLM 컨텍스트에도 가지 않는다 (기획 5.7).

## 3. 입력 — 무엇에서 뽑는가

네 종류의 신호를 쓴다. **한 신호가 축을 지배하지 못하게** 가중치를 갈랐다 —
지배하면 그 신호의 해석이 틀렸을 때 축 전체가 틀린다.

| 신호 | 가중치 | 왜 그 크기인가 |
|---|---|---|
| 일간의 강약 (신강/중화/신약) | ±18 | 셋 중 가장 크다. 명리 해석에서 일간의 강약이 실제로 가장 무겁게 쓰인다 |
| 오행 편중 (3개 이상 나타난 오행) | ±8 / 오행 | 8글자 균등이면 축당 1.6개이므로 3개는 이미 평균의 두 배다. 2로 낮추면 거의 모든 사주가 어딘가 "우세"가 된다 |
| 십신 그룹 빈도 | ±4 / 회, 축당 ±12 상한 | 낱개라 작다. 상한이 없으면 한 그룹이 많이 나온 사주에서 축을 혼자 결정한다 |
| 일간 음양 (양간/음간) | ±6 | 가장 거친 신호라 가장 작다. 결단·군중추종 두 축에만 쓴다 |

기준값은 모든 축이 **50**이다. 근거가 하나도 없으면 그 자리로 돌아간다.

## 4. 축별 매핑표

| 축 | 올리는 것 | 내리는 것 |
|---|---|---|
| `risk_appetite` 위험 감수도 | 신강, 화·목 우세, 식상·재성 | 신약, 수·금 우세, 인성 |
| `patience` 보유기간 선호 | 신강, 토·금 우세, 인성 | 화 우세, 식상 |
| `decisiveness` 결정 속도 | 양간 일간, 화 우세, 식상 | 음간 일간, 수·토 우세, 인성 |
| `loss_aversion` 손실 회피 | 신약, 수 우세, 인성·관살 | 신강, 화 우세, 식상 |
| `herd_tendency` 군중 추종 | 신약, 음간 일간, 인성·관살 | 신강, 양간 일간, 비겁 |

### 4.1 근거

명리의 통설적 해석을 그대로 옮긴 것이다.

- **일간의 강약** — 신강은 "스스로 버티는 힘이 도탑다"로 읽힌다. 그래서 위험 감수와
  보유 인내를 올리고 손실 회피와 군중 추종을 내린다.
- **오행** — 화(火)는 확산·속도, 목(木)은 성장·확장, 토(土)는 안정·중용, 금(金)은
  결단·수렴, 수(水)는 침잠·유연으로 읽힌다. 화가 결정 속도를, 토·금이 인내를,
  수가 손실 회피를 미는 것이 그 독법이다.
- **십신** — 식상(食傷)은 자기 재주를 밖으로 펼치는 기운이라 위험 감수·결정 속도를
  올리고, 인성(印星)은 받아들이고 지키는 기운이라 인내·손실 회피를 올린다.
  관살(官殺)은 규율·압박이라 손실 회피와 군중 추종 쪽이다. 비겁(比劫)은 자기 세력이라
  군중 추종을 내린다.
- **음양** — 양간은 발산, 음간은 수렴으로 읽어 결단 속도에 쓴다.

### 4.2 축들이 서로 독립이 아닌 것은 **의도다**

세로로 읽으면 신강이 `risk_appetite` 를 올리면서 `loss_aversion` 을 내리는 것이 보인다.
직교하게 만들 수도 있었지만 그러지 않았다 — 명리에서 일간의 강약은 실제로 그 둘을 같은
방향으로 설명하고, 억지로 떼어 놓으면 원 해석과 멀어진다.

이 성질은 테스트가 지킨다:
[`test_strength_moves_risk_and_loss_aversion_oppositely`](../back/tests/test_saju_engine.py).

## 5. 매핑 이후 — 숫자가 판단에 닿는 경로

```
사주 원국 + 강약
      │
      ▼  profile_mapping.to_profile_axes()      ← 이 문서
  ProfileAxes (숫자 6개)
      │
      ▼  사용자 보정 (source: saju → user_edited)
  InvestorProfile  ── DB 저장 (investor_profiles)
      │
      ▼  domain/fit.compute_fit(profile, metrics)   ← 순수 함수, LLM 없음
  FitScore (0~100 + 축별 우려 문장)
      │
      ▼  domain/verdict.combine(market, fit)        ← 결정론적, 단방향
  PersonalVerdict
```

**사주 원문은 첫 화살표 이후로 사라진다.** `compute_fit` 도 `combine` 도
`saju_summary` 를 읽지 않고, 판단 LLM 컨텍스트에도 들어가지 않는다.

## 6. 검증

| 무엇을 | 어떻게 | 어디 |
|---|---|---|
| 축이 항상 0~100 | 12개월 × 4시각 표본 전수 | `test_axes_are_always_in_range` |
| 같은 입력 → 같은 출력 | 두 번 호출해 비교 | `test_deterministic` |
| 강약이 두 축을 반대로 민다 | 신강·신약 표본 비교 | `test_strength_moves_risk_and_loss_aversion_oppositely` |
| 요약이 표시 전용 | 판단 경로가 읽지 않음 | `domain/fit.py`·`domain/verdict.py` 에 참조 없음 |

범위 검증이 특히 중요하다 — 벗어나면 `InvestorProfile` 의 Pydantic 검증이 500 으로
터지고, 그것은 **사용자 입력이 서버 오류가 되는 경로**다.

## 7. 아직 정하지 않은 것

- **재산정 허용 여부.** 생년월일시는 저장하지 않으므로(기획 11절, 그리고
  [`models/investor_profile.py`](../back/app/models/investor_profile.py)의 "생년월일시를
  저장하지 않는다" 절) 지금은 재산정이 불가능하다. 필요해지면 컬럼을 추가한다 —
  쓸지 안 쓸지 모르는 민감정보를 미리 받아 두는 것은 안 받는 것보다 나쁘다.
- **가중치의 실증.** 위 숫자들은 명리 해석에서 유도한 것이지 데이터로 맞춘 것이 아니다.
  **맞출 계획도 없다** — 백테스트로 사주 효과를 증명하려는 시도는 기획 4.2 가 명시적으로
  금지한다(증명하지 못하고, 시도했다는 사실 자체가 약점이 된다). 이 숫자들이 정당한
  이유는 예측력이 아니라 **사용자가 고칠 수 있다는 것**이다.
