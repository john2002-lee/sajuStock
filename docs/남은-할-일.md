<details>
<summary>원래 내용 (근거 기록용)</summary>

리비전 뿌리(`61b513b1f58a`, `down_revision=None`)가 그 테이블에 **컬럼을 더하는 것으로
시작한다.** 사슬 8개 전체에 `create_table("listed_companies")` 가 0건이다 — 여덟 컬럼과 unique
인덱스는 alembic 이력에 한 번도 등장하지 않는다. 지금 테이블이 존재하는 유일한 이유는
`create_all` 기본값이 True 이기 때문이다.

문서대로 `DB_CREATE_ALL_ON_STARTUP=false` + `alembic upgrade head` 로 새 Supabase 를 붙이면
**첫 리비전에서 `UndefinedTable` 로 멈춘다** — 신규 구축과 복구·이관 경로가 막혀 있다.
테스트도 `create_all` 을 쓰므로 이 사슬을 한 번도 태우지 않는다.

## 손대지 말 것 — 의도적으로 배제했고 지금도 유효한 판단

1. **검색 팔레트 ⇥ 와 서버 저장소 통합** — 10회차가 근거까지 적어 유보했다(로컬에 쌓인 것을
   서버로 올릴지 사용자에게 물어야 해서 별도 결정이 필요하다). 지금 요구되는 것은
   **안내 문구·⇥ 힌트를 사실로 맞추는 것뿐**(P1-18)이다. 통합을 밀지 말 것.
2. **공개 yfinance 경로에 새 키를 더 붙이지 말 것** — "잠글 이유가 있는 곳만 잠근다 / 키가 닿는
   표면을 넓히지 않는다" 는 근거는 유효하다([api/auth.py:9](../back/app/api/auth.py#L9)).
   약해진 것은 "남이 불러도 잃는 것이 없다" 쪽뿐이므로, 대응은 키가 아니라 **심볼 검증·서버
   캐시·백오프**다(P0-6).
3. **관리자 화면은 배치를 돌리지 않는다** — 관측과 실행을 분리한 판단이다. `/admin` 조회가 배치
   트리거가 되게 만들지 말고, 명시적 트리거(CLI 또는 `POST /admin/batches/snapshot`)를 따로 둔다.
4. **`browse/tokens.ts` 와 `screener/tokens.ts` 를 합치지 말 것** — 6열(시세)과 7열(지표)로 열
   정의가 실제로 다르다. 같은 이유로 **스크리너 지표 컬럼에 인덱스를 걸지 않은 17회차 결정**도
   2,747행 규모에서는 그대로 둔다.
5. **프런트 `ADMIN_EMAILS`(SEED_ADMINS) 마스터키를 없애지 말 것** — DB 와 무관하게 관리자를
   인정하는 이 경로가 "아무도 못 들어가는 상태" 를 막는 유일한 복구 수단이고, P2-2(마지막 관리자
   경쟁 조건)의 실질 완충이다.
6. **LangGraph 체크포인터는 계속 보류** — 한 요청이 짧게 끝난다는 근거는 유효하다. 단, 그 근거를
   코드로 강제해야 한다(P1-15) — **보류의 전제를 지키는 일이지 되돌리는 일이 아니다.**
