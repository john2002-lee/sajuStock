> **홈 온보딩 카드를 다시 걷어냈다 (2026-08-26).** 6.2 가 넣었던 "AI 셋이 각자
> 근거를 댑니다" 카드다. 홈에서 가장 많이 하는 일은 종목을 고르는 것이고 바로
> 위 검색 히어로가 이미 그 동작을 준다 — 설명 블록이 그 사이에 끼면 첫 화면이
> 제품 소개가 된다. 서비스 선택(`/`)의 제호도 같은 회차에 지웠다: 거기는 주식과
> 사주 중 하나를 고르는 갈림길이라, 그중 한쪽 이름을 머리에 걸면 아직 고르지도
> 않은 사람에게 답을 먼저 말하는 셈이다. **계정 메뉴는 남겼다** — `/` 에서
> 로그인할 수 있는 자리가 그 안뿐이었다.
>
> **대가: 2.2 의 "온보딩 0" 이 다시 열린다.** 처음 온 사람은 AI 판단이 있다는
> 것을 종목 상세에 들어가기 전까지 모른다. 그 안내를 꼭 홈에 둘 이유는 없으니,
> 다시 필요해지면 **종목 상세의 AI 버튼 옆이나 빈 상태**가 더 자연스러운 자리다.

> **P5 나머지도 끝냈다** — 6.3 일괄 AI 버튼을 브랜드 톤으로 올리고 **진행 개수**를
> 말하게 했다(`AI 분석 중 · 3종목 남음`). 예전에는 "AI 분석 중" 뿐이라 10종목을
> 걸어 놓고도 진행을 알 수 없었다. 6.5 팔레트는 `--pal-radius` 를 새로 두고
> 라이트의 2px 잉크 테두리를 헤어라인으로 낮췄다(신문 제호의 어휘였다).

> **§11 선행 확인이 전부 닫혔다.**
>
> 1. **순이익 행 이름** — 실측 확정. `NetIncome` 과 `NetIncomeCommonStockholders`
>    가 005930.KS 에서 **둘 다 44.26조로 같고**, `…IncludingNoncontrollingInterests`
>    (45.21조)만 비지배지분을 포함한다. 국내 재무 사이트의 "당기순이익" 이 앞의
>    둘이라 그쪽을 쓴다. 추가 네트워크 호출 0회 — 같은 프레임에서 행만 하나 더 읽는다.
> 2. **국내 분기 손익** — **온다. 5분기.** 7.2 가 "아무도 확인 안 했다" 고 적어 둔
>    것이 확인됐다. 다만 구현은 아직이다: `AnnualFinancial.fiscal_year: int` 로는
>    분기를 못 담아 `QuarterlyFinancial` 을 따로 뒀고, `get_income_stmt` 호출이
>    하나 더 붙는다(종목당 1~2초에 추가). **구현 완료.**
> 3. 저장 시점 — P4-a 에서 닫힘 (프런트 POST)
> 4. `price_at` — P4-a 에서 스키마에 들어감

> **P5 에서 한 것**
>
> - **6.1 상세** — `DetailTabs` 언더라인 → **pill 세그먼트**, 등락을 **알약**으로

> **남은 것**: 6.3 의 사이드바 행 리스킨, `MetricsRail`·`ValuationRail`(스펙이 "밀도 유지,
> 라운드 최소" 라 **바꿀 것이 없어** 손대지 않았다).

> **`segmented()` 가 P2 의 보류를 닫았다.** 그때 "P5 가 언더라인→pill 을 정하기
> 전에 API 를 만들면 짐작" 이라 미뤘는데, 이제 그 결정이 났다. 모양 둘을 **뜻으로**
> 가른다 — `pill` 은 *같은 대상의 다른 면*(종목 상세 탭 · 상승/하락), `underline`
> 은 *다른 대상으로 이동*(랭킹 ↔ 조건 검색). 셋이 같은 언더라인을 조금씩 다르게
> 그리고 있던 표류(`pb-2` vs `pb-[7px]`)도 함께 닫혔다.

> **`bg-up/12` 를 쓰지 않고 `--up-wash` 토큰을 만들었다.** 빌드 산출물을 열어 보고
> 바꿨다 — Tailwind 는 `color-mix` 를 못 쓰는 브라우저용 **폴백으로 불투명 원색**을
> 먼저 깐다(`.bg-up\/12{background-color:var(--up)}`). 그 브라우저에서는 빨강 배경
> 위에 빨강 글자가 얹혀 아예 안 읽힌다. 알파를 rgba 에 박으면 그 갈림이 없고,
> muted / line 램프가 이미 같은 이유로 같은 모양이다.

> **P4-b 에서 남은 것 하나.**
>
> - **공유 페이지가 404 화면을 200 으로 낸다.** 루트 `loading.tsx` 의 Suspense
>   경계 때문에 셸이 먼저 나가 헤더가 커밋된 뒤 `notFound()` 가 불린다 —
>   7.1.1 이 `/dashboard` 의 `redirect()` 에서 실측한 것과 **같은 함정**이다.
>   그때 답(`proxy.ts` 에서 앞단 차단)은 여기 쓸 수 없다: 링크 유효성은 DB 를
>   봐야 아는데 Edge 는 DB 를 못 본다. `noindex` 라 영향이 좁아 감수했다.
>
> **OG 이미지 — `woff2` 가 아니라 `ttf` 여야 했다.** `ImageResponse`(satori)는
> `ttf`·`otf`·`woff` 만 읽는다(`docs/.../image-response.md`). `next/font` 가 빌드
> 때 내려받는 것은 woff2 라 재사용할 수 없고, 폰트가 없으면 **한글이 빈 네모**로
> 렌더된다 — 종목명이 사라진 카드는 없는 것보다 나쁘다. Gothic A1 ExtraBold
> ttf 한 벌(2.2MB)을 `front/assets/` 에 뒀다. 런타임에 Google Fonts 를 부르는
> 방법도 있지만 카드를 그릴 때마다 외부 왕복이 붙고, 그쪽이 느리면 미리보기가
> 통째로 빈다.

> **P4-a 의 DB 테스트 11개 통과** (2026-08-25). 테스트 Supabase 프로젝트가 죽어
> 있어 한동안 못 돌렸다 — `(ENOTFOUND) tenant/user … not found` 는 자격증명이
> 아니라 **프로젝트가 응답하지 않는다**는 뜻이었다. 되살린 뒤 그대로 돈다.
>
> 그 과정에서 **테스트 하나를 고쳤다.** 소유자 헤더가 없을 때를 401/422 로 기대했는데
> 실제 계약은 **400** 이다. `get_owner_key` 가 근거를 갖고 있다 — 이 헤더는 인증이
> 아니라 **식별**이라 없는 것은 "권한이 없다" 가 아니라 "요청이 덜 왔다" 다.
> (프런트 BFF 는 그 앞에서 401 로 끊는다. 거기서는 신원이 세션의 문제라 뜻이 다르다.)
>
> **전체 스위트: 523개 중 521개 통과.** 실패 둘은 `test_admin.py` 이고 **이번
> 작업과 무관한 기존 실패**다. 증명해 두었다:
>
> - `test_admin_is_closed_when_the_key_is_missing` — 키가 **없는** 상태를 전제하는데
>   `back/.env` 에 `ADMIN_API_KEY` 가 있어 401 이 난다. `ADMIN_API_KEY=` 로 비우고
>   돌리면 **통과한다**(실측).
> - `test_actor_header_is_required_for_mutations` — `response.json()["detail"]` 을
>   읽는데 이 앱의 예외 핸들러는 `{"error": {"code", "message"}}` 를 낸다
>   (`core/exceptions.py:100`). 봉투가 바뀐 뒤 안 따라온 **낡은 단언**이다.

> **P3 의 §4.2 ④ "기록에 저장됨 + 공유" 는 넣지 않았다.** 저장할 곳이 아직 없다 —
> `advice_verdict` 테이블과 `/advice/verdicts` 가 **P4** 다. 없는 저장을 "저장됨"
> 이라고 말하는 것은 이 저장소가 가장 경계하는 종류의 거짓말이다(홈이 예시
> 데이터를 `SampleFrame` 으로 밝히는 것과 같은 이유). P4 에서 붙인다.

> P0-a·b 는 **색을 바꾸지 않았다.** 크기 스케일이 32종에서 10단으로 수렴하면서
> 일부 글자가 1~4px 움직인 것이 유일한 시각 변화다.

> **c3·c4 는 실행 중에 드러난 사실 때문에 방향이 바뀌었다.**
>
> - **c3 — 콘솔도 함께 바꾸기로 했다.** 콘솔 뷰는 서브트리에
>   `data-theme="terminal"` 을 못 박아(`ConsoleView.tsx`) **전역 다크 팔레트를
>   그대로 공유한다.** 10 장의 완화책("콘솔을 고정 참조로 격리")은 다크 팔레트를
>   **두 벌 유지**한다는 뜻이었다. 동결의 의미는 "재설계·재조판을 하지 않는다"
>   이지 "색을 박제한다" 가 아니고, 트레이딩 터미널에 뉴트럴 딥다크가 크림보다
>   어울린다 — 한 벌로 간다. **10 장 리스크 표의 그 줄은 닫혔다.**
> - **c4 — 하지 않는다.** 테마 기본값이 그새 `system` 으로 바뀌었다(3단:
>   시스템·라이트·다크). `cookie.ts` 주석이 *"사용자가 요청한 기본값이기도 하다"*
>   라고 적고 있어, 다크를 강제하면 그 결정을 되돌리게 된다. **"다크 퍼스트" 는
>   기본값 강제가 아니라 "다크를 먼저 잘 만든다" 로 좁힌다** — c3 가 그것이다.

> **문서를 믿지 말고 코드를 읽을 것.** 이 기획을 세우는 동안 `screen-spec.md §12` 를
> 믿고 "재무 탭이 미구현" 이라고 적었다가 틀렸다. 실제로는 완성돼 있었고 완료 기록도
> [`작업노트.md`](작업노트.md) 140행에 있었다. 같은 함정이 그 문서 4.2 절에도
> 기록돼 있는데 또 밟았다.

## 1. 결론부터 — 쟁점 B 를 닫는다

[`화면-고도화-기획.md`](화면-고도화-기획.md) 6장의 **쟁점 B(디자인 정체성: 유지 /
절충 / 전환)** 를 **"하이브리드 전환"** 으로 닫는다.

| | 결정 |
|---|---|
| 밀도 | **감성 영역은 MZ, 데이터 영역은 밀도 유지** |
| 테마 | **다크 퍼스트** + 비비드 액센트 1개 |
| 서체 | 명조 헤드라인 **전면 교체** (Gothic A1) |
| 시그니처 | **AI 판단 드로어** — 구조 유지, 연출 강화 |
| 재방문 | L1(프런트) + **L2(판단 이력 영속화)** |

### 왜 전면 전환이 아닌가

경쟁 서비스 대비 "UI 경쟁력" 지적(F-2)은 **(a) 밀도**와 **(d) 정체성** 둘로
좁혀져 있었다(그 문서 4장). **MZ 전환은 (d)를 풀지만 (a)를 악화시킨다** — 큰
라운드·큰 카드·넓은 여백은 밀도의 적이다.

토스증권이 MZ 로 읽히는 것은 여백 때문이 아니라 **감성을 진입·요약·결과에만 쓰고
데이터 영역은 촘촘하기 때문**이다. 그래서 영역을 갈라 적용한다.

| 영역 | 화면 | 적용 |
|---|---|---|
| **감성** | 홈 히어로 · AI 판단 결과 · 빈 상태 · 온보딩 · 로그인 | MZ 전면 — 큰 라운드, 굵은 타이포, 모션, 대비 |
| **데이터** | 표 · 차트 · 지표 레일 · 종목 상세 본문 | 밀도 유지 — 라운드 최소, tabular-nums, 헤어라인 |

### 그리고 제품 주장과의 정합

이 제품의 차별점 1순위는 **"AI 판단의 근거 투명성"** 이다(쟁점 A 후보 ①).
**근거를 읽는 화면이 장난스러우면 그 주장 자체가 깨진다.** 데이터 영역의 밀도를
지키는 것은 취향이 아니라 제품 주장을 지키는 일이다.

## 2. 진단 — 왜 지금 손대야 하는가

### 2.1 디자인 시스템이 "색" 에서 멈춰 있다

| 축 | 상태 |
|---|---|
| **색** | 완성. 9단계 muted 램프 · 다크 WCAG AA 재보정 · 차트 4색 색각이상 ΔE 검증 — **이 프로젝트 최고의 자산** |
| **타이포** | 토큰 없음. 폰트 크기 선언 **456곳**, 서로 다른 값 **32종**(8.5px~46px, 0.5px 단위) |
| **반경** | `radius: 0` 전역 강제 |
| **간격·그림자** | Tailwind 기본 + 임의값 혼용. 인라인 `style={{}}` **418곳 / 104파일** |

**지금 `globals.css` 를 갈아도 색만 바뀌고 형태는 안 바뀐다.** 리뉴얼 비용의
대부분이 여기 있고, 그래서 토큰 완성이 P0 다.

### 2.2 "다시 안 오는" 이유 — 코드에서 나온 5개

**① 매일 달라지는 것이 이 앱만의 것이 아니다.** 홈이 주는 것은 지수·등락상위·일정
으로 전부 다른 데도 있다. 이 앱에만 있는 **AI 판단은 종목 상세에 들어가야만** 만난다.

**② 쌓이는데 안 보여준다.**

| 쌓이는 것 | 어디에 | 화면에 |
|---|---|---|
| 최근 본 종목 5개 | localStorage | 홈 칩 ✅ |
| 관심종목 + 그룹 + 순서 | 서버 DB | 대시보드 ✅ |
| **AI 판단 결과** | React Query 캐시(`ADVICE_STALE_MS` 10분) | ❌ **없다** |
| 알림 조건 | 서버 DB | 표에만 |

**종목당 LLM 4회를 태워 만든 판단이 캐시 만료되면 사라진다.** 이 제품에서 가장
비싼 산출물인데 기록이 안 남는다.

**③ 알림이 배달되지 않는다.** `AlertToggle`·`AlertCondition` 로 조건을 적고 저장까지
되는데 백엔드에 **스케줄러도 발송기도 없다**(`apscheduler|celery|cron|smtp|push`
검색 0건 — `watchlist` 모델·스키마·서비스에만 존재). 재방문 트리거로 쓸 유일한
장치가 껍데기다. → **L3 로 분리, 이번 범위 밖.**

**④ 돌아왔을 때 "그 자리" 가 없다.** `/dashboard` 는 항상 목록 첫 종목을 연다.

**⑤ 공유할 것이 없다.** `?ai=1` 딥링크는 있으나 받은 사람은 자기 계정으로 다시
돌려야 한다. OG 이미지도 캡처용 카드도 없다.

## 3. 디자인 토큰

### 3.1 색 — 다크를 기본으로

지금 `[data-theme="terminal"]` 은 **크림 잉크(`#e8e3d8`)** 를 쓴다. 따뜻한 종이
은유의 잔재라, 뉴트럴로 바꾸는 것만으로 현대적으로 읽힌다.

```
--paper         #0A0B0E   거의 검정, 미세하게 푸른
--surface       #14161B
--surface-hover #1B1E25
--ink           #F2F3F5   뉴트럴 화이트 (크림 아님)
--ink-2         #C9CCD2
--accent        #C6F24E   비비드 라임
```

> **액센트는 데이터 색이 아니다.** CTA · 활성 상태 · 브랜드에만 쓰고 **차트 · 표
> 안에는 들어가지 않는다.** 라임을 고른 이유가 여기 있다 — 등락 빨강/파랑, MA
> 금색/틸그린 어디와도 안 겹쳐서 **데이터 영역에 새어 들면 바로 티가 난다.**
> 바이올렛은 하락 파랑과, 시안은 MA60 틸과 가까워 새어도 모른다.

> **`--accent` 를 재사용하지 않고 `--brand` 를 새로 뒀다.** 실행 중에 확인한
> 사실이다 — 기존 `--accent`(금색 #e8b04b)는 브랜드 색이 아니라 **콘솔(2b)의
> 색**이다. 쓰이는 곳이 콘솔 액션 · 터미널 캐럿 · 팔레트 히트뿐이고,
> `AdviceTrigger` 의 `tone="accent"` 도 `ConsoleView` 에서만 쓴다. 그걸 라임으로
> 갈면 **동결하기로 한 콘솔만** 바뀌고 정작 주 화면은 그대로다.
>
> 짝으로 `--brand-ink: #0a0b0e` 를 둔다. **테마를 따라가지 않는 고정 값**이다 —
> 라임은 두 테마에서 밝기가 같아서, 전경을 `--ink` 로 두면 다크에서 밝은 글자가
> 밝은 라임 위에 올라간다. 고정하면 라이트 13.5:1 · 다크 15.2:1 로 양쪽 안전하다.

**불변**: `--up` `--down` `--ma20` `--ma60` `--wuxing-*`.
색각이상 ΔE 9.2 / 정상시야 ΔE 17.0 검증 결과를 무효로 만들지 않는다.

### 3.2 타입 스케일 — 32종 → 10단

P0 의 본체. 456곳을 이 표로 기계 치환한다.

| 토큰 | px | 쓰는 곳 | 흡수하는 기존 값 |
|---|---|---|---|
| `--text-10` | 10 | mono 미세 라벨 · 탭바 | 8.5 · 9 · 9.5 · 10 |
| `--text-11` | 11 | 라벨 · 각주 | 10.5 · 11 |
| `--text-12` | 12 | 캡션 · 힌트 | 11.5 · 12 |
| `--text-13` | 13 | 표 셀 · 보조 본문 | 12.5 · 13 |
| `--text-14` | 14 | 본문 | 13.5 · 14 · 14.5 |
| `--text-16` | 16 | 카드 제목 | 15 · 16 · 16.5 · 17 |
| `--text-20` | 20 | 섹션 제목 | 18 · 19 · 20 |
| `--text-26` | 26 | 화면 제목 | 22 · 24 · 25 · 26 |
| `--text-34` | 34 | 헤드라인 · 가격 | 28 · 30 · 32 · 34 · 36 · 38 |
| `--text-48` | 48 | 화면의 최상단 — AI 최종 판정 · 종목 헤드라인(md 이상) | 44 · 46 |

0.5px 단위가 32종 중 7종(9.5 · 10.5 · 11.5 · 12.5 · 13.5 · 14.5 · 16.5)이다.
이것들이 사라지는 것만으로도 화면이 정돈된다.

> **이름을 px 값으로 둔 것과 미세 구간이 두 단인 것은 실행 중에 정해졌다.**
>
> - **이름**: 처음에는 `--text-2xs`~`--text-4xl` 이었는데 그러면 **Tailwind 기본
>   스케일을 덮는다.** 그 이름들은 사주 화면 10개 파일이 이미 쓰고 있어
>   (`features/saju/components/*`), 주식과 무관한 화면이 조용히 틀어진다. 같은
>   이유로 반경도 `--radius-xs/sm/md/lg`(Tailwind 기본)와 `--radius-card/pillar`
>   (사주 팔레트) 양쪽을 피해 숫자로 갔다. 이 파일의 muted / line 램프가 이미
>   내린 결론이기도 하다 — *"semantic 이름은 단계가 늘어날 때마다 의미가 무너져
>   숫자로 바꿨다"*.
> - **미세 구간 2단(10 · 11)**: 9단 안에서 9.5·10·10.5·11px 을 한 단으로 합치려
>   했는데 그 구간에만 **154곳**이 몰려 있었다. 합치면 10px 라벨이 10% 커지고,
>   그 자리가 높이 고정인 `MobileTabBar`(`--tabbar-h: 62px`)와 줄바꿈 사고 이력이
>   주석에 남은 `Masthead` 우측 컨트롤이다. `--label-size` 도 라이트 10.5 /
>   터미널 9.5 로 **테마별로 다른 값을 의도**하고 있어 한 단으로 뭉개면 터미널의
>   촘촘함이 사라진다.
> - **위쪽 두 단(34 · 48) 사이가 넓다.** 처음에 36·38 을 48 로 붙였다가 되돌렸다 —
>   콘솔 헤드라인의 가격이 38px 인데 48 로 가면 **+26%** 고, 하필 콘솔은 이번에
>   **동결하기로 한 뷰**다. 34 로 붙이면 -10% 라 그쪽이 가깝다. `--text-48` 은
>   지금 쓰는 곳이 없고, P3 에서 AI 최종 판정이 그 자리를 받는다.

### 3.3 반경 — radius 0 폐기, 데이터 영역은 예외

--radius-md   14px    카드 · 패널
--radius-lg   20px    히어로 · 바텀시트 · 드로어
--radius-full 999px   pill

`globals.css` 의 `button,input,select,textarea { border-radius: 0 }` 리셋을 제거한다.

**표 셀 · 헤어라인 그리드(`gap-px + bg-line-16` 관용구)는 0 을 유지한다.**
여기 라운드를 주면 헤어라인 기법이 깨지고 밀도가 무너진다.

## 4. 시그니처 — AI 판단 드로어

**드로어 구조는 건드리지 않는다** — `fixed`, 데스크탑 438px / 모바일 전체시트,
**SSE 단일 마운트**. 2a·2b 두 레이아웃이 동시에 렌더돼 있어도 드로어는 하나여야
스트림이 갈라지지 않는다. 안쪽 연출만 바꾼다.

### 4.1 지금

```
열림 → 안내문 + 멈추기 버튼
     → AgentCard 가 도착 순서대로 append
     → AgentSkeleton 1장이 남은 자리를 지킴
     → FinalDecision (bg-ink 반전, 34px 판정 + 신뢰도 5칸)
```

기다리는 동안 **몇 명이 무슨 관점으로 보고 있는지 알 수 없다.**

### 4.2 바꿀 것

**① 시작할 때 3인을 먼저 소개한다.** 슬롯 3개를 미리 세우고 각자의 관점을 라벨로
보여준다. 기다림이 "빈 화면" 에서 "누가 아직 말 안 했나" 로 바뀐다.

**② 불일치를 상단에 고정 표시한다 — 정체성의 시각화.**

```
● 긍정   ● 중립   ● 부정      ← 3인이 갈렸다
● 긍정   ● 긍정   ● 긍정      ← 만장일치
```

> **어휘를 고쳤다.** 기획 초안은 `BUY / HOLD / AVOID` 로 그렸는데, 그건 **최종
> 판정**(`Verdict`)의 어휘다. 에이전트가 내는 것은 `stance: 긍정 | 중립 | 부정`
> 으로 *"내가 읽은 자료에 대한 평가"* 이지 매수 판단이 아니다. 둘을 같은 말로
> 쓰면 "저널리스트가 BUY 라고 했다" 는 오해가 생긴다.
>
> 색도 **등락색을 쓰지 않는다.** 긍정에 `--up`(상승 빨강)을 주면 "이 종목이
> 오른다" 로 읽힌다 — 판단 영역과 시세 영역을 섞지 않는다는 규칙이 여기서도
> 같은 방향으로 걸린다.

README 가 말하는 *"판단 근거를 이해하기 쉽게 보여준다"* 를 화면이 처음으로 지키는
자리다. 지금은 카드 3장을 다 읽어야만 알 수 있다.

**③ 최종 판정 = 화면에서 가장 큰 것.** `--text-4xl`(48px) + 신뢰도 카운트업 +
5칸 미터가 차오르는 연출. `animate-fade-up-slow` → 스프링 이징.

**④ 끝난 뒤 `기록에 저장됨` + `공유` 버튼.** 여기가 L2 와 만나는 지점이다.

**⑤ 규칙 기반 폴백 표식은 유지.** `RULE_BASED` 조회 테이블과 점선 테두리는
신뢰의 근거라 없애면 안 된다. 유니온이 넓어질 때 컴파일 에러가 나는 구조도 그대로.

## 5. 재방문 — L1 + L2

### 5.1 L1 (프런트만)

- 마지막 본 종목 복귀 (`/dashboard` 가 첫 종목 대신)
- AI 판단 결과 로컬 보관 + 홈 "내 판단 기록" 섹션
- 오늘 내 종목 중 가장 많이 움직인 것
- 공유 카드

### 5.2 L2 (백엔드 포함)

**백엔드 구현 완료** (2026-08-25). 기획안에서 둘이 바뀌었다.

```
테이블  advice_verdicts        UNIQUE (owner_key, code)
  id · owner_key · code · symbol · name
  decision · confidence · source(llm|fallback|timeout) · answer
  price_at · agent_opinions(jsonb) · share_id · created_at · updated_at

POST   /api/v1/advice/verdicts                    판단 저장 (같은 종목이면 덮어씀)
GET    /api/v1/advice/verdicts?limit=             내 이력
POST   /api/v1/advice/verdicts/{code}/share       공유 켜기 → share_id
GET    /api/v1/advice/verdicts/shared/{share_id}  공유 조회 (소유자 불필요)
```

- **`shared(bool)` 을 없앴다.** `share_id IS NULL` 이 곧 비공개라 두 컬럼이 같은
  것을 두 번 말한다 — 둘이 어긋나는 상태(`shared=true` 인데 id 가 없는)를 만들 수
  있는 스키마는 그 상태가 언젠가 생긴다.
- **공유 켜기 엔드포인트가 늘었다.** 기획에는 조회만 있었는데 켜는 동작이 없으면
  `share_id` 를 발급할 곳이 없다. 두 번 눌러도 **같은 id** 를 준다 — 새로 발급하면
  먼저 보낸 링크가 죽는다.
- `summary` 대신 `answer` 다. 백엔드 `AdviceStreamDecision` 의 필드 이름이 그것이라,
  다른 이름을 쓰면 복사하는 자리마다 매핑이 하나 생긴다.

**라우터를 `stocks.py` 에 넣지 않았다.** `/stocks/advice` 는 판단을 **만드는** 문이라
동시 실행 상한·실행 예산·SSE 프레이밍이 붙어 있고, 여기는 평범한 CRUD 다. 같은
파일에 두면 열 때마다 어느 쪽 규칙이 걸리는지 확인해야 한다.

**신원은 이미 있다.** [`app/_data/owner.ts`](../front/src/app/_data/owner.ts) 가
로그인이면 계정, 아니면 브라우저로 규칙을 단일 소유한다. 그리고 **AI 판단은 이미
계정 필수다** — `readAccountOwnerKey()` 가 익명에게 `null` 을 주고 `canUseAdvice()`
가 그걸 본다. 익명 판단이 없으므로 이력 소유권이 애매할 일이 없다.

### 5.3 보관 정책 — **종목당 1건 upsert + 소유자당 100건 LRU**

근거: 판단 1건이 `Decision` + `AgentOpinion[]` 3인(각자 요약 + stance + 인용 문서
배열) ≈ **2~5KB jsonb** 이고, `MAX_BULK_SYMBOLS = 10` 이라 **일괄 분석 한 번에
10건이 한꺼번에 생긴다.** 상한이 없으면 두 번만 돌려도 홈 목록이 같은 종목들로
도배된다.

### 5.4 공유 — **unlisted**

공유 버튼을 누를 때만 랜덤 `share_id` 로 스냅샷을 만든다. `robots` 로 색인을 막는다.

> **`personal` 필드는 무조건 제외한다.** `Decision.personal`(`PersonalVerdict`) 에는
> **사용자의 투자 성향 6축과 적합도**가 들어 있다. 사주에서 유래한 값이라, 공유
> 카드에 새면 개인의 성향 프로파일이 공개된다. 취향 문제가 아니라 안전 기본값이다.

### 5.5 홈에 앉는 훅

```
┌ 내 판단 기록 ────────────────────────┐
│ 삼성전자    HOLD  신뢰도 68%          │
│ 8월 18일 · 그 뒤 +4.2%      ← 이 줄  │
│ SK하이닉스  BUY   신뢰도 81%          │
│ 8월 15일 · 그 뒤 -1.1%                │
└──────────────────────────────────────┘
```

**"그 뒤 +4.2%" 가 재방문의 핵심이다** — 판단이 맞았는지 확인하러 오게 만든다.
기준가는 저장 시점의 값을 `price_at` 에 같이 적는다(나중에 히스토리에서 역산하는
것보다 정확하고 싸다).

판단 기록이 없는 신규 사용자에게는 그 자리에 **온보딩 카드**가 들어간다 —
지금 없는 온보딩이 여기서 생긴다.

## 7. 재무 탭 확장

### 7.1 순이익 — 작업량 거의 없음

[`fundamentals.py`](../back/app/integrations/yfinance/fundamentals.py) 의 `_annual()`
이 **이미 손익계산서 프레임을 손에 쥐고 있다.** 행 이름 상수와 `_first_row()` 헬퍼
패턴이 그대로 있다.

```python
_REVENUE_KEYS = ("TotalRevenue", "OperatingRevenue")
_OPERATING_INCOME_KEYS = ("OperatingIncome", "TotalOperatingIncomeAsReported")
```

`_NET_INCOME_KEYS` 한 줄 + `AnnualFinancial` 필드 하나 + 프런트 열 하나.
**추가 네트워크 호출 0회** — 같은 프레임에서 행만 하나 더 읽는다.

후보 라벨 `NetIncome` · `NetIncomeCommonStockholders` ·
`NetIncomeContinuousOperations` 는 **추정이다.** 이 파일은 *"전부 실측으로 확인했다,
추측이 아니다"* 를 모듈 주석에 못 박아 둔 곳이라 **실제 프레임을 찍어 확정한다.**

### 7.2 분기 실적 — 실측이 먼저

`get_income_stmt(freq="quarterly")` 로 같은 경로를 쓸 수 있으나 셋이 걸린다.

| 걸리는 것 | 내용 |
|---|---|
| **국내 커버리지 미확인** | 이 파일이 문서화한 실측은 *"국내 종목은 `trailingPE`/`priceToBook` 가 항상 None"* 류다. 분기 손익이 국내에 오는지는 아무도 확인 안 했다 |
| **응답 지연 증가** | 지금도 종목당 1~2초. 호출이 하나 더 붙는다 (TTL 캐시가 반복 비용은 흡수) |
| **스키마 불일치** | `AnnualFinancial.fiscal_year: int` 로는 분기를 못 담는다. `QuarterlyFinancial` 별도 정의 필요 |

**표본 3종목(005930.KS · 000660.KS · 247540.KQ — 이 파일이 이미 쓰는 표본)으로
프레임을 찍어 본 뒤 결정한다.** 데이터가 안 오면 "화면은 있는데 국내에선 늘 비는"
탭이 된다.

**R4 가 기존 원자까지 포함하는 이유**: `Chip`(10.5) · `Delta`(13.5) ·
`SectionLabel`(12) · `StatRow`(12.5 / 13) 넷은 폰트 크기를 **숫자 prop 으로 받아**
인라인 style 로 심는다. `size={11}` 같은 호출부가 딸려 있어 R1 의 기계 치환 대상이
아니다 — 토큰 이름을 받도록 API 를 바꾸는 일이고, 그건 새 원자를 만드는 작업과
같은 결정이라 여기로 미뤘다. R1 이 남긴 44곳 중 8곳이 이것이다(나머지는 동적 값 ·
safe-area `calc()` · 유동 `clamp()` · 차트 엔진 옵션으로 **인라인이 맞는 자리**다).

### R4 실행 결과 — 소비자가 있는 것만 만들었다

원자 여섯을 한 번에 만들려다 **호출부를 먼저 세어 보고 셋으로 줄였다.** 소비자가
없는 원자는 API 를 짐작으로 정하게 되고, 그렇게 정한 API 는 실제 화면이 붙을 때
거의 맞지 않는다.

| 만든 것 | 근거 |
|---|---|
| **`TextSize` 유니온 + `TEXT_CLASS`** | 원자 넷의 숫자 `size` prop. P0 에서 미룬 빚 |
| **`button()`** | 솔리드/아웃라인 버튼 **25곳**, 여백이 `px-3`·`px-3.5`·`px-4` 로 표류 |
| **`Card`** | 점선 안내·빈 상태 상자 **8곳 / 6변형** (`p-3.5`·`p-3`·`px-6 py-16`…) |

| 미룬 것 | 근거 |
|---|---|
| `Badge` | 사본이 셋인데 **셋 다 다르게 생겼다**(테두리·색). 합치면 옵션만 남는다 |
| `Segmented` | 6.1 이 "언더라인 → pill" 을 **P5 에서 정한다**. 그 전에 API 를 정하면 짐작이다 |
| `Meter` | 소비자가 `FinalDecision` 하나뿐이고, **P3 가 정확히 그 카드를 다시 만든다** |
| `CountUp` | 소비자 0. P3 이 도입한다 |

**`button()` 은 컴포넌트가 아니라 클래스 생성기다.** 이 앱의 버튼은 절반이
`<button>` 이 아니다 — 필터 칩·페이지네이션·'전체 보기' 는 상태가 URL 에 있어
`<Link>` 다. 컴포넌트로 만들면 `as` prop 층이 생기고 그 층이 `<Link>` 의
`scroll`·`prefetch` 를 전부 다시 통과시켜야 한다.

#### 숫자 `size` prop — 문자열 토큰이 아니라 유니온으로 좁혔다

`Chip`·`Delta`·`SectionLabel`·`StatRow` 넷이 폰트 크기를 숫자로 받아 인라인 style 로
심고 있었다. `size="sm"` 같은 문자열 토큰으로 바꾸려다 접었다 — **`Delta` 가 숫자를
필요로 한다.** 방향 표식 아이콘 크기를 글자 크기에서 도출하기 때문이다(`size * 0.78`,
아이콘의 광학 크기 보정). 문자열이면 그 안에서 다시 숫자로 되돌리는 표가 필요하다.

그래서 숫자는 두고 **스케일 밖 값을 타입 오류로 만들었다.** `tsc` 가 즉시 다섯 곳을
잡아냈다 — `10.5`(×2) · `12.5`(×2) · `15`. 스케일을 지키는 일이 사람의 기억에서
컴파일러로 넘어갔다.

덤으로 `Delta` 의 `gap` prop 을 없앴다. **넘기는 호출부가 하나도 없었다** — 옵션만
남아 있던 자리다.

**R2 의 관건**: `RANKING_GRID`(6열)와 `SCREENER_GRID`(7열)가 각자 `tokens.ts` 에
**근거와 함께** 분리돼 있다. 그 판단은 맞다 — **열 정의는 계속 따로 두고 조판만
합친다.** 억지로 합치면 어느 화면에도 맞지 않는 열 폭이 된다.

### R2 실행 결과 — 사본이 생각보다 많았다

기획은 `browse` vs `screener` 두 벌로 봤는데 **표는 네 벌, 좁은 행은 다섯 벌**이었다.
홈의 `TopByCap`(표)과 `CalendarList`·`MoverList`(좁은 행)가 같은 것을 각자 그리고
있었다. `market/components/table/` 에 넷을 만들어 흡수했다.

| 새 조각 | 흡수한 사본 |
|---|---|
| `TableShell` | 랭킹 표 · 조건 검색 표의 데스크탑/모바일 분기 |
| `StockListRow` | 모바일 랭킹 카드 · 모바일 조건 검색 카드 · 홈 등락 상위 행 |
| `StockNameCell` | 위 셋 + 데스크탑 행 둘 + 오늘의 일정 |
| `HEAD_ROW`·`ROW_LINK`·`CARD_LINK` | 머리 행·본문 행·좁은 행의 선·여백·hover |

**`table/index.ts` 의 "행·카드는 여기 오지 않는다" 를 고쳤다.** 그 근거는 *"열이
다르면 행도 다르다"* 였는데, 좁은 행은 그리드를 쓰지 않아 열 개념이 없다 — 세
화면이 같은 것을 그리고 있었다는 사실이 그 증거다. 데스크탑 그리드 행은 규칙대로
각자 남는다.

**합치지 않은 것도 근거를 남겼다.** `TopByCap` 의 종목명은 16px 이고 공용은 14px 인데,
그 차이가 그 파일이 적어 둔 *"같은 데이터의 다른 밀도"* 다. 크기를 프롭으로 갈라
합치면 근거가 사라지고 옵션만 남는다. 조건 검색의 3갈래 빈 상태도 그대로 뒀다.

### R3 실행 결과 — **`density` prop 은 틀린 설계였다**

기획은 "3벌 → 1벌 + `density` prop" 이었다. 코드를 읽고 **철회했다.**

세 행은 레이아웃이 진짜로 다르다 — 8열 그리드(`WatchRow`) · 340px 3줄 스택
(`WatchRowCompact`) · 모바일 2단 카드(`WatchCard`). `WatchRowCompact` 주석이 그
이유를 이미 적어 두었다: *"`WatchRow` 는 1180px 전체 폭을 전제로 한 줄에 열 개를
담는다 … 작업대에서 목록에 주어지는 폭은 340px 다."* 셋을 프롭 하나로 합치면
`table/index.ts` 가 경고한 바로 그것 — **근거가 사라지고 옵션만 남는다.**

**중복된 것은 레이아웃이 아니라 로직이었다.** 다섯 조각이 세 파일에 글자 하나까지
같았다.

| 새 조각 | 흡수한 것 |
|---|---|
| `useWatchRowDrag` | `useSortable` 배선 + `CSS.Transform` 인라인 style |
| `SelectOrDrag` | 체크박스↔드래그 핸들 분기 (감싸는 기하는 호출부가 준다) |
| `isOverseas` (model) | `market === "NASDAQ" \|\| market === "NYSE"` 3사본 |

결과: `useSortable` 직접 호출이 **3파일 → 1파일**, `NASDAQ` 하드코딩이 컴포넌트에서
사라졌다. 시장이 하나 늘 때 고칠 곳이 하나다 — 예전에는 한 곳을 빠뜨려도 화면은
멀쩡히 그려지고 **가격 앞의 `$` 만 조용히 사라졌다.**

> **줄 수는 크게 안 줄었다.** 이 저장소의 관례대로 새 조각에 근거 주석을 붙였기
> 때문이다. P1 의 성과 지표는 줄 수가 아니라 **"X 가 바뀔 때 고칠 곳의 수"** 다.

## 9. 실행 순서

```
P0  토큰 확정 + 인라인 456곳 치환             front only
P1  중복 정리 (R2 · R3)                       front only
P2  shared/ui 원자 확장 (R4)
P3  AI 드로어 연출 — 시그니처                 ← 톤의 기준점
P4  L2 백엔드 + 판단 이력 화면 + 공유
P5  화면 리스킨  상세 → 홈 → 대시보드 → 랭킹/스크리너
P6  재무 확장   순이익 → (실측) → 분기
P7  문서 동기화
```

- **P1 이 P5 앞**: 중복을 남기면 같은 디자인을 3번 적용한다
- **P3 이 P5 앞**: 시그니처가 정해져야 나머지 화면 톤이 정해진다
- **P4 는 P3·P5 와 독립**: 이력 화면은 로컬(L1)로 먼저 세우고 API 가 준비되면 소스만 교체
- **P6 이 마지막**: 백엔드 실측이 프런트 리뉴얼을 막으면 안 된다. 순이익만 먼저 P5 에 얹어도 된다

각 단계 검증:

```bash
cd front && npx tsc --noEmit && npm run lint && npm test && npm run build
```

라우트가 바뀌었으면 `npm run build` 를 먼저 돌린다 — `.next/types` 가 빌드
산출물이라 지우지 않으면 `tsc` 가 없어진 라우트를 찾으며 실패한다.

기획 단계에서 닫지 못한 것. 착수 전에 실측한다.

1. **손익계산서 순이익 행 이름** — 실제 프레임 확인
2. **국내 분기 손익 존재 여부** — 표본 3종목
3. ~~**`advice_verdict` 저장 시점**~~ — **닫혔다: 프런트가 완료 후 POST.**

   코드를 읽고 뒤집었다. 기획은 *"전자(백엔드 자동 저장)가 낫다"* 고 적었는데,
   `services/advice_stream.py` 가 그것을 비싸게 만든다:

   - 엔드포인트가 **일부러** DB 를 스트림 밖에서 읽는다 — *"제너레이터 안에서
     DB 를 만지면 수십 초 동안 세션이 붙잡힌다."* 자동 저장은 그 규칙을 깬다.
   - 최종 판단이 나가는 **출구가 셋**이다: 정상 4단계 · 예산 만료 착지 ·
     `decided` 가드. 세 곳을 모두 건드려야 하고, 그 파일은 취소 의미론에 대한
     경고가 곳곳에 박힌 자리다.

   **대가는 위조 가능성이다.** 이 경로로 아무 판단이나 넣을 수 있다. 다만 넣을 수
   있는 곳은 **자기 목록**뿐이고(`owner_key` 는 서버가 세션에서 채운다, 본문으로
   받지 않는다), 공유는 링크를 아는 사람만 보는 비공개 기본값이다. 남의 기록을
   바꾸거나 공개 목록을 오염시키는 경로는 없다. 스크린샷 위조와 같은 수준의
   위험이라 판단해 이쪽을 골랐다 — **뒤집고 싶으면 여기가 그 자리다.**
4. **"그 뒤 +4.2%" 기준가** — `price_at` 을 스키마에 두는 안으로 잠정 결정(5.5)
