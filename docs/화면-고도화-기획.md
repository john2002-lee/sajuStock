## 2. 예비 사용자 피드백

원문 그대로 세 건이 나왔다.

### F-1. "로그인하면 관심종목 리스트를 보여주고, 그중 하나를 자세히 보여줬으면"

**말 그대로가 아니라 구조 요구다.** 지금 구조는 이렇다.

```
로그인  →  /watchlist 로 리다이렉트  →  관심종목 표
                                          │ 종목명 클릭
                                          ▼
                                     /stocks/[symbol]   ← 전체 화면 전환, 목록이 사라짐
```

사용자가 원하는 것:

```
로그인  →  관심종목 목록 + 선택된 1종목의 상세를 한 화면에   (마스터–디테일)
```

**차이가 실제로 만드는 것** — 지금은 5종목을 비교하려면 목록↔상세를 5번 왕복해야
하고, 매번 목록의 스크롤 위치·선택 상태를 잃는다. 리서치 도구의 핵심 동작이
"내 종목들을 훑다가 하나를 파고든다"인데, 그 동작이 화면 전환으로 끊긴다.

관련 사실: 로그인 후 목적지는 이미 `/watchlist` 다 ([login/page.tsx](../front/src/app/login/page.tsx)).
목적지는 맞고 **그 화면의 밀도가 부족한 것**이다.

### F-2. "타 사이트 서비스에 비해 UI 경쟁력이 떨어진다"

이 문장은 그대로 작업으로 옮길 수 없다. 4장에서 분해한다.

## 3. F-1 설계 — 관심종목을 "리서치 작업대"로

> **이 장은 기록이다.** 여기서 만든 `/watchlist` 작업대는 9장에서 대시보드로
> 합쳐졌다 — 라우트·파일 이름은 그때 전부 바뀌었다. 판단의 근거는 그대로 유효하고
> 지금 대시보드가 그것을 그대로 쓴다. **현재 구조는 9장을 본다.**

### 3.1 목표 화면

`/watchlist` 를 목록 화면에서 **작업대**로 승격한다. 왼쪽에서 훑고, 오른쪽에서 판다.

```
┌─ Masthead ─────────────────────────────── 검색 · 테마 · 계정 ─┐
├─ 헤더 (종목수 · 그룹 · 알림) · 그룹 탭 · 정렬 ────────────────┤
├──────────────────────┬────────────────────────────────────────┤
│ 목록 (~340px)        │  선택된 종목 상세                       │
│  ▸ 삼성전자   +1.2%  │   헤드라인 · 현재가 · 등락              │
│  ● SK하이닉스 -0.4%  │   [담기] [AI 판단]                      │
│  ▸ NAVER      +0.1%  │   차트                                  │
│  ▸ 카카오     -2.1%  │   뉴스 / 리포트 / 재무 탭 │ 지표 레일   │
│                      │                                         │
│  ＋종목 추가          │                                         │
└──────────────────────┴────────────────────────────────────────┘
```

- **선택 상태는 URL 이 갖는다** — `/watchlist/005930`. 공유 가능한 주소와 뒤로가기를 얻는다.
- **기본 선택** — `/watchlist` 는 목록의 **첫 종목** 상세를 그대로 그린다 (리다이렉트 없음).
- **모바일(<768)** — 분할이 성립하지 않는다. 목록만 두고, 행을 누르면 지금처럼
  `/stocks/[symbol]` 전체 화면으로 간다. 요구의 본질(왕복 절감)은 데스크탑 문제다.

### 3.2 라우트 구조 — 여기가 이 작업의 핵심이다

**쿼리스트링(`/watchlist?symbol=`)으로 하면 안 된다.** 선택을 바꿀 때마다 페이지
세그먼트 전체가 다시 돌아 `getWatchlist` 를 매번 새로 부르는데, 목록을 들고 있는
[`useWatchlistMutations`](../front/src/features/stock/watchlist/hooks/useWatchlistMutations.ts) 는
`useState(initial)` 이라 **새로 받은 목록을 쓰지도 않는다.** 클릭마다 버려지는 백엔드
조회가 하나씩 붙는다.

대신 **레이아웃이 목록을 소유하는 동적 세그먼트**로 간다. App Router 에서 레이아웃은
자식 간 이동에서 다시 렌더되지 않는다 — 목록 fetch 도, 클라이언트 상태(그룹·정렬·
선택·일괄 AI 진행)도 그대로 살아 있고 오른쪽만 바뀐다.

```
app/watchlist/
├── layout.tsx          ← 제호 + WatchlistBoard(목록). 선택 이동에도 다시 안 돈다
├── page.tsx            ← /watchlist        : 첫 종목 상세
├── [code]/page.tsx     ← /watchlist/005930 : 그 종목 상세
├── loading.tsx         ← 상세 칸만 스켈레톤 (목록은 그대로)
├── error.tsx           ← 상세 칸의 오류 경계 (목록은 경계 밖이라 그대로 선다)
└── _components/
    ├── WatchlistBoard.tsx     (목록 + 보기 전환 + 상세 슬롯)
    ├── WatchlistDetail.tsx    (상세 조립 + AI 드로어)
    └── {Board,Detail}Skeleton.tsx
```

`loading.tsx`·`error.tsx` 는 `[code]/` 가 아니라 **한 단계 위**에 둔다. Next 는 이
둘을 같은 세그먼트의 `page.tsx` **와 그 아래 전부**를 감싸는 경계로 만들므로,
`/watchlist` 와 `/watchlist/[code]` 가 파일 하나를 공유한다.

목록 조회(`loadWatchlist`)는 처음 `watchlist/_data.ts` 에 뒀다가, 대시보드가 같은
목록을 쓰게 되면서 **`app/_data/watchlist.ts`** 로 올렸다 (7.5).

레이아웃은 `children` 을 받아 `WatchlistBoard` 안의 오른쪽 칸에 꽂는다 — 서버
컴포넌트를 클라이언트 컴포넌트에 `children` 으로 넘기는 표준 형태다.

### 3.3 데이터 비용 — 캐시는 이미 있다

> **정정**: 1차 정리에서 "history·content 서버 캐시가 없어 선행 작업" 이라고 적었는데
> **틀렸다.** [`apiGetCached`](../front/src/lib/api/client.ts) 가 `cache: "force-cache"` +
> `revalidate`(장중 60초 / 장외 900초, 뉴스는 REVALIDATE_STATIC)로 이미 캐시한다.
> 캐시 키가 URL 이라 **종목별로 따로 채워진다.**

그래서 선택 전환 비용은 두 갈래다.

| 경우 | 비용 |
|---|---|
| 캐시 HIT (누군가 최근에 본 종목) | 거의 즉시 |
| 캐시 MISS | `history`(0.13초) → `content`·`fundamentals` 병렬(1~2초) ≈ **최대 2초** |

MISS 를 사용자가 멈춤으로 겪지 않게, **상세 패널만 `<Suspense>` 로 스트리밍**한다.
목록은 그대로 있고 오른쪽만 스켈레톤 → 채워짐. `loading.tsx` 가 그 일을 한다.

### 3.4 상세 패널을 무엇으로 만들 것인가

[`EditorialView`](../front/src/app/stocks/[symbol]/_components/EditorialView.tsx) 는 자체
`Masthead` 를 들고 있어 그대로 끼울 수 없다. **본문을 분리해 두 화면이 공유한다.**

```
EditorialView (app/stocks/[symbol]/_components/)   ← Masthead + 아래 것
   └─ StockDetailBody (features/stocks/components/) ← 헤드라인 · 액션줄 · 차트 · 탭 · 레일
```

`StockDetailBody` 는 `features/stocks` 에 두되, **다른 feature 의 조각은 슬롯으로 주입**
받는다 — feature 간 직접 import 금지 규칙(CONVENTIONS)을 지키기 위해서다.

```tsx
<StockDetailBody
  detail={detail}
  actions={<><WatchToggle …/><ViewToggle/><AdviceTrigger/></>}  // watchlist·advice
  railExtra={<MarketOverviewList indices={indices}/>}            // market
/>
```

작업대에서는 `actions` 에서 `ViewToggle`(콘솔 전환)을 빼고, `railExtra` 에 시장 지수
대신 아무것도 넣지 않는다 — 지수는 홈에 있고, 좁은 칸에서 우선순위가 낮다.

### 3.5 AI 판단 드로어

`AdviceProvider` + `AdviceDrawer` 는 **선택된 종목과 함께 움직여야 한다.** 레이아웃이
아니라 `[code]/page.tsx` 안에 둔다 — 종목을 바꾸면 통째로 다시 마운트되어 이전 종목의
스트림·결과가 남지 않는다.

목록 쪽 **일괄 AI 분석**(`useBulkAdvice`)은 레이아웃의 클라이언트 상태라 선택을 바꿔도
계속 돌고, 행에 붙은 진행 뱃지도 유지된다. 이 둘이 섞이지 않는다.

### 3.6 목록 칸에서 덜어낼 것 / 남길 것

목록 폭이 1180px 에서 ~340px 로 줄어든다. 지금 `WatchRow` 가 한 줄에 담는 것은
체크박스 · 종목명 · 코드 · 현재가 · 등락률 · 스파크라인 · 평가손익 · 알림 토글 ·
알림 조건 · AI 판단 — **열 개다. 340px 에 들어가지 않는다.**

| 요소 | 작업대 목록 | 근거 |
|---|---|---|
| 종목명 · 등락률 | **남긴다** | 훑는 목적 그 자체 |
| 스파크라인 | 남긴다 | 폭을 거의 안 먹고 정보 밀도가 높다 |
| AI 판단 뱃지 | 남긴다 | 일괄 분석 결과를 보는 자리 |
| 현재가 | 남긴다 (2행 배치) | |
| 체크박스 · 드래그 핸들 | 남긴다 | 일괄 AI 분석의 대상 선택이 여기서 일어난다 |
| 평가손익 · 알림 토글 · 알림 조건 | **접는다** | 340px 에서 셋을 더하면 종목명이 잘린다 |

→ 기존 `WatchRow`(넓은 표)와 별개로 **작업대용 좁은 행**이 필요하다. `WatchCard`
(모바일 카드)가 이미 비슷한 밀도라 그쪽을 출발점으로 쓴다.

**접는 것을 없애지는 않는다 — 데스크탑 보기를 둘로 나눈다.**

| 보기 | 목적 | 구성 |
|---|---|---|
| **분할** (기본) | 훑다가 하나를 판다 | 좁은 목록 + 상세 |
| **표** | 관리한다 | 예전 화면 그대로 — 전체 폭 8열, 알림 조건 편집·보유·평가손익 |

좁은 칸에 열 개를 우겨넣어 전부 못 읽게 만드는 대신, 목적이 다른 두 보기를 뒀다.
전환은 그룹 탭 줄의 토글이고 **클라이언트 상태**다 — 정렬·그룹과 달리 공유할 가치가
없는 개인 취향이고, URL 에 실으면 상세 라우트마다 물고 다녀야 한다.

### 3.7 지금 있는 것 중 버리지 말 것

그룹 탭 · 정렬 · 드래그 순서 · 알림 조건 · 일괄 선택 · **일괄 AI 판단**
(`MAX_BULK_SYMBOLS` 상한). 특히 일괄 AI 판단은 경쟁 서비스에 없고 작업대 구조와
정확히 맞는다 — 목록에 판단 뱃지가 뜨고, 클릭하면 오른쪽에서 근거가 펼쳐진다.

## 7. 대시보드 — 로그인 직후 도착하는 화면 (2026-08-18 구현)

> **이 장도 기록이다.** 여기서 만든 타일 대시보드는 9장에서 nav+상세 구조로 다시
> 짜였고 타일 둘(`SummaryStrip`·`WatchlistDigest`)은 지워졌다. 화면 폭(7.4)과
> 실데이터 규칙(7.2)은 그대로 유효하다.

요구는 두 문장이었다. **"로그인하면 대시보드로 넘어가게" + "화면을 넓게, 빈 공간을
최소화."** 앞쪽은 새 화면이고 뒤쪽은 전 화면에 걸린 폭 문제라, 따로 처리했다.

### 7.1 왜 작업대(F-1)로 대신하지 않았나

세 화면의 목적이 다르다.

| 화면 | 무엇을 보는가 |
|---|---|
| 시장 현황 `/` | **시장.** 신원이 없어도 같은 화면 |
| 대시보드 `/dashboard` | **내 현황 전체를 얕게** |
| 작업대 `/watchlist` | **한 종목을 깊게** |

작업대에 요약 타일을 얹으면 상세가 밀려 내려가 F-1 이 산 것("하나를 깊게")이 깨지고,
홈에 관심종목을 넣으면 담아 둔 것이 없는 사람에게 늘 빈 칸이 남는다. 그래서 셋을 두고
대시보드에서 깊이 들어가는 순간 작업대로 넘긴다.

### 7.1.1 로그인을 요구하는 유일한 화면 (2026-08-18 결정)

> 처음에는 익명으로도 열어 뒀다가, **"대시보드는 로그인했을 때만"** 으로 바꿨다.

나머지는 전부 익명으로 쓸 수 있다 — 관심종목까지도. 여기만 다른 이유는 이 화면이
"내 것" 을 한자리에 모으는 자리여서다. 브라우저를 바꾸면 사라지는 익명 목록 위에
"내 현황" 을 세우면, 다른 기기에서 들어온 사람에게 빈 대시보드를 보여주고 그게
고장인지 원래 그런 것인지 알 방법을 주지 않는다.

막는 층이 둘이다 — `/admin` 이 이미 쓰던 구조 그대로다.

| 층 | 하는 일 |
|---|---|
| `proxy.ts` `redirectAnonymousDashboard` | 세션 쿠키가 **아예 없는** 요청을 렌더 전에 `/login` 으로 **307** |
| `dashboard/page.tsx` `currentUser()` | 진짜 판단. Edge 는 DB 를 못 보므로 쿠키 유효성은 여기서만 안다 |

**프록시 층이 없으면 화면이 깜빡인다.** 루트 `loading.tsx` 의 Suspense 경계 때문에
셸이 먼저 흘러나가, 페이지의 `redirect()` 는 307 이 아니라
`<meta http-equiv="refresh" content="1;url=/login">` 로 내려간다(실측). 로그아웃
상태로 주소를 치면 **가려던 곳도 아닌 홈 골격이 1초** 보인다.

진입점도 함께 숨겼다 — 안 그러면 누를 때마다 로그인으로 튕기는 미끼가 된다.
탭바는 그 칸을 빼서 넷이 되고, 홈 제호 버튼은 같은 자리에서 '관심 종목' 으로 바뀐다.
로그인 화면의 "로그인하지 않아도 **전부** 쓸 수 있습니다" 도 사실이 아니게 되어
고쳤다 — 이제 달라지는 것이 둘이다(기기 간 동기화 · 대시보드).

### 7.2 실데이터로만 채웠다

4.2 의 정정이 여기 규칙이 됐다 — **없는 것은 넣지 않는다.**

| 타일 | 출처 |
|---|---|
| 요약 띠 (관심 n · 그룹 n · 알림 n · 평가손익 % · AI 분석 n/n) | `Watchlist` 집계 |
| 지수 4카드 | `GET /markets/overview` |
| 내 관심 종목 상위 8행 | `Watchlist.items` |
| 등락 상위 | `getMovers()` — 스냅샷이 비면 `SampleFrame` |
| 오늘의 일정 | `getCalendar()` |
| AI 판단 현황 | `WatchItem.verdict` 집계 |

업종 집계 · 시장 뉴스 · 아침 브리핑 · 포트폴리오 시계열은 **자리를 만들지 않았다.**

### 7.3 이 화면이 하지 않는 것

- **AI 분석을 돌리지 않는다** — 종목당 LLM 4회다. 화면을 여는 것만으로 시작되면 안 된다.
- **다시 정렬하지 않는다** — 작업대에서 정한 순서를 그대로 쓴다. 여기서 등락률 순으로
  세우면 같은 목록이 두 화면에서 다른 순서로 보인다.
- **편집 컨트롤을 두지 않는다** — 체크박스·드래그·알림 조건은 작업대의 것이다.

### 7.4 화면 폭 — 전 화면 1180 → 1440

**토큰 하나로 뒀다.** `--shell: 1440px` → `max-w-shell`. 15개 파일에 박혀 있던
`max-w-[1180px]` 을 전부 이것으로 바꿨다. 화면마다 폭이 다르면 이동할 때 제호와 본문의
왼쪽 축이 흔들려 같은 사이트가 아닌 것처럼 읽힌다.

더 늘리지 않은 이유는 **표는 넓을수록 좋지만 문장은 아니어서**다. 로그인처럼 본문이
좁아야 하는 화면은 컨테이너를 줄이지 않고 안쪽에서 좁힌다(`max-w-[420px]`).

폭을 올리자 드러난 빈 공간도 함께 메웠다 — 차트의 `md:max-w-[748px]` 고정을 걷어냈다.
본문 칸이 1000px 을 넘는데 차트만 748 에 멈추면 그 오른쪽이 통째로 빈다.

### 7.5 함께 정리한 것

- **`SampleFrame` 에 `when` 을 붙였다.** 홈과 대시보드가 같은 헬퍼(`Sample`)를 각자
  갖고 있었다 — 두 번째 사용처가 생겼으니 공통으로 올렸다 (CONVENTIONS).
- **`loadWatchlist` 를 `app/_data/` 로 옮겼다.** 작업대와 대시보드가 함께 쓴다.
  한쪽 라우트의 `_components/` 에 두면 다른 쪽이 남의 내부를 깊게 참조한다.
  CONVENTIONS 의 '예외적으로 허용되는 배치' 에 한 줄 추가했다.
- **모바일 탭바가 다섯 칸이 됐다** — 대시보드 · 시장 · 검색 · 탐색 · 관심.
  `/` 의 라벨을 **홈 → 시장**으로 바꿨다. 대시보드와 나란히 서면 둘 다 "첫 화면" 으로
  읽혀 무엇이 다른지 알 수 없다. 제호는 여전히 `/` 로 간다.
- 로그인 리다이렉트 3곳(`redirect` · 구글 · 매직링크)이 `/dashboard` 로 간다.
  `robots.ts` 에 `/dashboard` 를 막았다 — 사용자별 데이터다.

라우트에 `ƒ /dashboard` 가 올라온다. 서버 렌더로 여섯 타일이 전부 그려지는 것을
확인했고, 프로덕션 빌드 CSS 에 `.max-w-shell{max-width:var(--shell)}` 와
`--shell:1440px` 이 들어간 것을 파일에서 되읽어 확인했다.

**브라우저 확인은 여전히 못 했다** (3.9 와 같은 이유 — 미리보기 창이 인라인 스크립트를
막아 하이드레이션이 안 일어나고, 연결된 크롬이 없다). 실제로 봐야 하는 것:
1440px 에서 각 타일의 여백 · 1280 미만에서 레일이 접히는 모양 · 5칸 탭바가 375px 에서
눌리지 않는지 · 넓어진 차트의 가독성.

## 9. 대시보드 = 작업대 — 두 화면을 하나로 (2026-08-18)

> 요구: **"좌측에 nav bar 를 만들고 watchlist 종목을 세로로 나열, 맨 위 종목을 stock
> page 처럼."** 그 구조가 이미 `/watchlist` 작업대였다 — 그대로 만들면 같은 화면이
> 둘이 된다. 그래서 **합쳤다**(사용자 결정). 타일은 상세 아래로 내렸다.

### 9.1 무엇이 어디로 갔나

| 옛것 | 새것 |
|---|---|
| `/watchlist` · `/watchlist/[code]` | `/dashboard` · `/dashboard/[code]` — `proxy.ts` 가 307, **종목 코드까지 살려서** |
| `WatchlistBoard` · `WatchlistDetail` | `DashboardBoard` · `DashboardDetail` |
| 대시보드 타일 6개 | 4개 — 지수 · 등락 · 일정 · AI 현황. `SummaryStrip` 과 `WatchlistDigest` 는 **삭제** |

`SummaryStrip`(종목수·그룹·알림·평가손익)은 nav 헤더(`WatchlistHeader`)와 정렬 컨트롤이
같은 값을 이미 보여 준다. `WatchlistDigest`(관심종목 상위 8행)는 **nav 그 자체**가 됐다.
합치고 나니 둘 다 같은 화면 안에서 같은 숫자를 두 번 말하는 자리였다.

### 9.2 시장 타일이 두 열 아래인 이유

상세 옆(3열)에 두면 1440px 에서 상세가 좁아진다 — 상세는 차트를 품고 있어 폭이 곧
정보량이다. 오른쪽 칸 안(상세 아래)에 두면 1012px 로 좁아지고, 무엇보다 그 칸이
`hidden md:grid` 라서 **모바일에서 통째로 사라진다.** 두 열 아래 전체 폭이면 폭도 얻고
모든 폭에서 보인다.

레이아웃이 그린다 — `page.tsx` 에 두면 종목을 바꿀 때마다 시장을 다시 조회한다.

### 9.3 합치면서 잃은 것 / 잃지 않은 것

**잃지 않았다** — 그룹 탭 · 정렬 · 드래그 순서 · 알림 조건 편집 · 보유·평가손익 ·
일괄 선택 · 일괄 AI. 좁은 nav 에 안 들어가는 것은 **표 보기**가 그대로 받는다.

**잃었다** — 익명 사용자가 담아 둔 종목을 **볼 화면이 없다.** 담기(`WatchToggle`)는
익명 쿠키로 그대로 저장되고 로그인하면 `claimAnonymousWatchlist` 가 계정으로 옮기므로
**데이터가 사라지지는 않는다.** 다만 로그인 전에는 확인할 수 없다. 8장의 로그인 게이트와
이번 합침이 함께 만든 결과다 — 되돌리려면 게이트를 다시 열거나, 익명용 목록 화면을
따로 둬야 한다.

### 9.4 함께 정리한 것

- **`WatchRowCompact` 가 `href` 를 prop 으로 받는다.** 라우트를 하드코딩하고 있었는데
  이번에 한 번 바뀌었다 — 도메인 컴포넌트가 URL 을 알면 라우트가 움직일 때마다
  거기까지 따라온다. 라우트는 app 계층이 정한다.
- **모바일 탭바가 넷(로그인) / 셋(익명)** — 관심 칸이 대시보드와 같은 곳을 가리키게
  되어 뺐다.
- 제호의 '관심 종목' 버튼 셋(홈·탐색·조건 검색)이 **'대시보드'** 가 되고 로그인했을
  때만 뜬다. 콘텐츠 링크(`FindBand` 타일 · 404 안내)는 남긴다 — 항상 보이는 크롬이
  아니고, 눌러서 도착한 로그인 화면이 이유를 말한다.
- `app/watchlist/` 라우트를 지웠다. 리다이렉트는 `proxy.ts` 한 곳에 있다.
- `src/app/componets/`(오타 폴더, 비어 있었다)를 지웠다.

### 9.5 검증

```
npx tsc --noEmit · npm run lint · npm test(84개) · npm run build   전부 통과
```

**라우트를 지우면 `npm run build` 를 먼저 돌려야 한다** — `.next/types` 의 라우트 타입이
빌드 산출물이라 `tsc` 가 없어진 라우트를 찾으며 실패한다. 이번에 그걸로 한 번 막혔다.

실제 요청으로 확인한 것:

```
/watchlist        → 307 /dashboard
/watchlist/005930 → 307 /dashboard/005930      (코드 보존)
/dashboard        → 307 /login                 (익명)
/dashboard/005930 → 307 /login                 (익명)
```

합쳐진 화면 자체는 **게이트를 잠시 우회해** 서버 렌더를 확인하고 즉시 되돌렸다 —
nav 6종목(`/dashboard/{코드}` 링크) · `[340px_1fr]` 격자 · 상세(삼성전자 헤드라인 ·
투자 지표 · 밸류에이션 · 리포트 탭 · '전체 상세') · 타일 4종(KOSPI · 상승/하락률 상위 ·
오늘의 일정 · AI 판단 현황)이 전부 한 응답에 있다. 되돌린 뒤 307 을 다시 확인했다.

**브라우저는 여전히 못 봤다** — 로그인한 상태의 실제 화면(타일이 상세 아래에 오는지,
1440px 에서 nav·상세·타일의 여백, 4칸 탭바)은 직접 띄워서 봐야 한다.
