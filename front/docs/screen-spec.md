# 화면 설계서

`front/src/` 가 실제로 구현하고 있는 화면의 설계서다. 코드가 정본이며, 이 문서는
`app/` 라우트와 `features/*/*/components` 를 읽어 확인한 구조만 기술한다.

- 구조 규칙: [`CONVENTIONS.md`](../CONVENTIONS.md) — 폴더·의존 방향·별칭
- 백엔드 계약: [`back/docs/api-spec.md`](../../back/docs/api-spec.md)
- 기획 문서: [`docs/product-plan.md`](../../docs/product-plan.md) 8장(프론트엔드 화면 요구사항)

---

## 0. 서비스가 둘이다

| 서비스 | 라우트 그룹 | 주소 | 셸이 붙이는 것 |
|---|---|---|---|
| **주식** | `app/(stock)/` | `/stock` · `/stocks/**` · `/dashboard/**` | 제목 `%s · 종목 원장` · 시세/투자 면책 푸터 |
| **사주** | `app/(saju)/` | `/saju` | 제목 `%s · 투자 성향` · 사주 고지 푸터 · `ServiceBar` |
| *(계정)* | `app/(account)/` | `/login` · `/signup` · `/verify` | 양쪽 고지 푸터 |

**괄호 폴더는 URL 에 나타나지 않는다.** `app/(stock)/stock/page.tsx` 의 주소는
`/stock` 이다.

`/`(S-06)는 어느 서비스도 아니다 — 둘 중 하나를 고르는 화면이다. `/admin` 과
`not-found` · 루트 `error` 도 그룹 밖이라 푸터를 각자 든다.

### 로딩·오류 폴백이 두 층이다

| 파일 | 걸리는 범위 | 무엇을 그리나 |
|---|---|---|
| `app/loading.tsx` · `app/error.tsx` | 더 가까운 경계가 없는 **모든** 라우트 | 서비스를 모르는 최소 셸 |
| `app/(stock)/stock/loading.tsx` · `error.tsx` | `/stock` 만 | 시장 현황 골격 · "시장 현황을 불러오지 못했습니다" |

예전에는 시장 현황 골격·오류가 **루트에** 있었다. 그래서 사주 온보딩이 터져도
"지수·등락 상위 조회 중 문제가 발생했습니다" 라고 말했고, 로그인으로 이동할 때도
홈 골격이 잠깐 떴다. 서비스가 갈리면서 그 둘은 자기 세그먼트로 내려갔다.

**서비스를 오가는 길은 셋뿐이다** — S-06 의 카드 둘, S-01 의 `ProfileBand`(주식 →
사주), 그리고 모든 화면 푸터의 이동 줄. 제호(`Wordmark`)는 서비스를 바꾸지 않는다:
주식 화면에서 누르면 `/stock`, 사주 화면에서는 `/saju` 로 간다. 종목을 보던 사람이
제호를 눌렀을 때 "어느 서비스를 쓰시겠습니까" 가 뜨면 안 되기 때문이다.

## 2. 공통 설계

### 2.1 레이아웃 골격

S-06 · S-01 · S-02 · S-04 · E-03 이 같은 골격을 공유한다. **S-00 대시보드는 예외다** —
사이드바가 뷰포트 왼쪽 끝에 붙는 앱 셸이라 이 컨테이너 밖으로 나갔다 (6.3).

```
┌────────────────────────────────────────────────────────┐
│ Masthead  제호(서비스 홈) + 캡션 │ 검색 · 테마 · 액션    │  border-b-2 border-ink
├────────────────────────────────────────────────────────┤
│                                                        │
│   main  max-w-shell(1440px) · px-4 (md:px-8) · pt-26   │
│                                                        │
├────────────────────────────────────────────────────────┤
│ Footer  서비스 고지 · 서비스 이동 줄 · 데이터 출처       │  서비스 레이아웃이 붙인다
└────────────────────────────────────────────────────────┘
   주식:  MobileTabBar  (대시보드) · 시장 · 검색 · 탐색   <768, fixed bottom
   사주:  ServiceBar    투자 성향 · 서비스 선택 · 주식     <768, fixed bottom
```

| 요소 | 사양 | 구현 |
|---|---|---|
| 컨테이너 | **`max-w-shell`**(= `--shell: 1440px`), 좌우 `px-4` → `md:px-8`, 상단 `pt-[26px]` | 각 `page.tsx` · 토큰은 [globals.css](../src/app/globals.css) |
| 하단 여백 | 기본 `pb-[30px]`. 모바일 고정 요소가 있는 화면은 `pb-24`(상세) / `pb-28`(시장·사주·404) / `pb-40`(대시보드) | 고정 바에 콘텐츠가 가리지 않게 |
| 제호 | `Wordmark` — 클릭 시 **지금 있는 서비스의 홈**(`home` prop). 캡션에 기준 시각·장 마감 안내 | [Masthead.tsx](../src/shared/components/layout/Masthead.tsx) |
| 우측 슬롯 | `search` · `ThemeToggle` · `action` 세 자리. 검색/AI 는 feature 소유라 슬롯 주입 | 〃 |
| 푸터 | `service` 에 따라 고지가 갈린다 — `"stock"`(시세·투자 면책 + 출처) / `"saju"`(종목 미추천·생년월일시 미저장) / `"both"`. 서비스 이동 줄은 항상 있다 | [Footer.tsx](../src/shared/components/layout/Footer.tsx) |
| 탭바 (주식) | 높이 `--tabbar-h: 62px`, `bottom-0 z-30`, `md:hidden`. 탭 44×44. 로그인하면 4개(대시보드 · 시장 · 검색 · 탐색), 아니면 3개 | [MobileTabBar.tsx](../src/shared/components/layout/MobileTabBar.tsx) |
| 서비스 바 (사주) | 같은 높이·같은 규격, 칸은 셋 — 투자 성향 · 서비스 선택 · 주식. 세션을 읽지 않는다 | [ServiceBar.tsx](../src/shared/components/layout/ServiceBar.tsx) |

탭바 위에 액션 바를 얹는 화면(S-00)은 `bottom: calc(var(--tabbar-h) + var(--safe-b))`
로 띄운다 — 두 요소가 각자 `bottom-0` 을 잡으면 정확히 겹친다.

**폭은 화면마다 다르지 않다.** 전 화면이 `max-w-shell` 하나를 쓴다 — 화면을 오갈 때
제호와 본문의 왼쪽 축이 흔들리면 같은 사이트가 아닌 것처럼 읽힌다. 1180 → 1440 으로
올린 것은 1440·1920 모니터에서 좌우를 크게 버렸기 때문이고, 더 늘리지 않은 것은 표는
넓을수록 좋지만 문장은 아니기 때문이다. 로그인처럼 본문이 좁아야 하는 화면은 컨테이너를
줄이지 않고 **안쪽에서** 좁힌다(`max-w-[420px]`) — 제호는 다른 화면과 같은 자리에 선다.

`/stock` 의 탭 라벨은 **홈 → 시장**이다. 대시보드와 나란히 서면 둘 다 "첫 화면" 으로
읽혀 무엇이 다른지 알 수 없다.

**사주 화면이 주식 탭바를 들지 않는다.** 예전에는 들었다 — `current` 를 주지 않아
아무 칸도 켜지지 않게 했지만, 칸 자체가 시장·종목 검색·종목 탐색이라 **거기 없는
기능을 하단에 상시 광고하는** 상태였다. 서비스가 갈리면서 `ServiceBar` 로 바뀌었다.

### 2.2 반응형

브레이크포인트는 Tailwind 기본값을 쓰고 실제로는 두 개만 의미가 있다.

| 폭 | 이름 | 기준 |
|---|---|---|
| < 768 | 모바일 | 1열 스택 · 하단 탭바 · 팔레트 전체화면 · 고정 액션 바 |
| ≥ 768 | `md` 데스크탑 | 다열 그리드 · 상단 액션 노출 · 드로어 438px |
| ≥ 1280 | `xl` | S-00 우측 레일 380px 분리 (1024~1279 는 본문 아래로 접힘) |

화면별 그리드:

| 화면 | 모바일 | md | xl |
|---|---|---|---|
| S-00 요약 띠 | 2열 | 5열 | 5열 |
| S-00 본문/레일 | 1열 | 1열 | `[1fr_380px]` |
| S-00 등락 상위 | 탭 전환(`MoversTabs`) | 2열 병렬 | 레일이라 탭 전환 |
| S-01 지수 카드 | 2열 | 4열 | 4열 |
| S-01 등락 상위 | 탭 전환(`MoversTabs`) | 2열 병렬 | 2열 (레일 없음 — 전체 폭) |
| S-02 본문/레일 | 1열 (레일이 본문 아래로) | `[1fr_292px]` | 〃 |
| S-03 3분할 | 세로 스택, 중앙이 `order-first` | `214px │ 1fr │ 252px` | 〃 |
| S-00 nav/상세 | 카드(`WatchCard`), 상세 없음 | `[340px_1fr]` 분할 — nav + 상세 / 또는 전체 폭 표 | 〃 |

모바일 전용 규칙 — 차트는 `-mx-4` 풀블리드 + 높이 220px, 검색 팔레트는 전체화면,
AI 드로어는 하단에서 올라오는 전체화면 시트다.

### 2.3 테마

| 항목 | 값 |
|---|---|
| 기본 | 에디토리얼 라이트 (종이 `#fdfbf6` / 잉크 `#1a1a17`) |
| 다크 | `[data-theme="terminal"]` (배경 `#0e1116` / 잉크 `#e8e3d8`) |
| 저장 | 쿠키. 루트 레이아웃이 서버에서 읽어 첫 HTML 의 `<html data-theme>` 에 담는다 |
| 전환 | 마스트헤드 `ThemeToggle` |

깜빡임과 하이드레이션 불일치가 없다 — 서버·클라이언트가 처음부터 같은 값을 본다.
S-03 콘솔 뷰는 서브트리에 `data-theme="terminal"` 을 직접 박아, `?view=console`
딥링크로 들어와도 첫 프레임부터 다크다. 전역 테마는 바꾸지 않는다.

### 2.4 디자인 토큰

전부 [globals.css](../src/app/globals.css) 에 있다. 2계층 구조다 — `:root` 원시 변수(SVG·차트가 직접
참조) + `@theme inline` Tailwind 매핑.

**색**

| 계열 | 토큰 | 용도 |
|---|---|---|
| 배경 | `--paper` `--surface` `--surface-hover` | 지면 · 패널 · 호버 |
| 전경 | `--ink` `--ink-2` | 본문 |
| 흐림 | `--muted-30` … `--muted-75` (9단계) | 보조 텍스트. opacity modifier 금지 |
| 선 | `--line-14` … `--line-35`, `--line-control` | 헤어라인 / 컨트롤 경계(3:1 보장) |
| 등락 | `--up: #c8352c` `--down: #1f57c3` | **상승 빨강 · 하락 파랑 (국내 관례)** |
| 반전 | `--on-ink-*` | `bg-ink` 위 전경 |
| 강조 | `--accent: #e8b04b` | 콘솔 액션 · 터미널 캐럿 |

다크 테마는 알파 램프를 통째로 올려 가장 낮은 단계도 WCAG AA(4.5:1)를 넘긴다 —
숫자 이름은 라이트와 짝을 맞추기 위한 것이지 알파 값이 아니다.

**타이포**

| 변수 | 서체 | 용도 |
|---|---|---|
| `--font-serif-kr` | Noto Serif KR | 종목명 · 헤드라인 · AI 답변 |
| `--font-sans-kr` | IBM Plex Sans KR | 본문 기본 |
| `--font-mono` | IBM Plex Mono | 라벨 · 숫자 · API 메모 |
| `--font-serif-en` | Instrument Serif | 영문 부제 |

`.num` 유틸이 모든 숫자에 mono + `tabular-nums` 를 강제한다 (표·가격·축 정렬).

**기하**

- **radius 0 이 기본.** `button/input/select/textarea` 의 브라우저 기본 라운드를 지운다.
  예외는 `.dot`(원형 마커 3곳)과 `.pill`(알림 토글)뿐이다.
- `--tap: 44px` — 터치 히트 영역 최소치 (WCAG 2.5.5 / iOS HIG).
- `--safe-b: env(safe-area-inset-bottom)` — 하단 고정 요소가 홈 인디케이터에 먹히지 않게.
- 검색 팔레트 기하는 `--pal-*` 로 테마별·뷰포트별로 통째로 갈아끼운다 (2.6 참고).

**모션**

`fadeUp` · `slideIn`(드로어) · `popIn`(팔레트) · `sheetUp`(모바일 시트) · `wfpulse`(스켈레톤) ·
`dotSpin`(스피너). `prefers-reduced-motion: reduce` 에서 전부 0.01ms 로 죽인다.

### 2.5 공통 상호작용

## 3. S-01 · 시장 현황 (**주식 서비스의 홈**)

경로 `/stock` · [page.tsx](../src/app/(stock)/stock/page.tsx) · 서버 컴포넌트 ·
`export const revalidate = 0`

이 화면은 `/` 에 있었다. 그 자리는 서비스 선택(S-06)이 갖는다 — 사주로 들어온 사람에게
첫 화면이 코스피 지수인 것은 다른 제품을 연 것과 같다. 주소가 내려오면서 바뀐 것은
셋뿐이다: 제호가 `/stock` 으로 돌아오고, 탭바 시장 칸이 `current="market"` 이 되고,
푸터는 `(stock)` 레이아웃이 든다.

정적 프리렌더로 두면 `next build` 가 빌드 머신에서 백엔드에 접속해야 한다. 데이터
신선도는 fetch 단위 `revalidate` 가 책임지므로 실제 백엔드 호출은 여전히 주기적이다.
`force-dynamic` 이 아니라 `revalidate = 0` 인 이유는 CONVENTIONS 의 '이 프로젝트에
한정된 제약' 절에 있다 — 전자는 라우트의 모든 fetch 를 `no-store` 로 강제한다.

### 6.1 세 화면의 역할이 다르다

| 화면 | 무엇을 보는가 | 신원 |
|---|---|---|
| S-01 시장 현황 `/stock` | **시장** | 없어도 같은 화면 |
| S-00 대시보드 `/dashboard` | **담아 둔 종목 하나를 깊게 + 시장을 얕게** | **로그인 필수** |
| S-02 종목 상세 `/stocks/[symbol]` | 아무 종목이나 깊게 | 없어도 같은 화면 |

담아 둔 종목을 여는 화면은 이제 **하나**다. 같은 것을 두 주소로 두면 어느 쪽이 본체인지
흐려지고, 고칠 때마다 두 번 고쳐야 한다.

### 6.2 로그인을 요구하는 유일한 화면이다

나머지는 전부 익명으로 쓸 수 있다 — 종목 상세도, ⇥ 로 담는 것도(`anon:` 쿠키).
여기만 다른 이유는 이 화면이 **"내 것"을 한자리에 모으는 자리**여서다. 브라우저를
바꾸면 사라지는 익명 목록 위에 "내 현황" 을 세우면, 다른 기기에서 들어온 사람에게 빈
대시보드를 보여주고 그게 고장인지 원래 그런 것인지 알 방법을 주지 않는다.

막는 층이 둘이다. 관리자 화면(`/admin`)과 같은 구조이고 같은 한계다.

| 층 | 하는 일 | 한계 |
|---|---|---|
| [proxy.ts](../src/proxy.ts) `redirectAnonymousDashboard` | 세션 쿠키가 **아예 없는** 요청을 렌더 전에 `/login` 으로 307 | Edge 라 DB 를 못 봐 쿠키가 유효한지는 모른다 |
| [layout.tsx](../src/app/(stock)/dashboard/layout.tsx) `currentUser()` | 진짜 판단. 신원이 없으면 `redirect("/login")` | — |

**프록시 층이 없으면 화면이 한 번 깜빡인다.** 루트 `loading.tsx` 가 만든 Suspense
경계 때문에 셸이 먼저 흘러나가, 페이지의 `redirect()` 는 307 이 아니라
`<meta http-equiv="refresh" content="1;url=/login">` 로 내려간다(실측 — `/admin` 의
`notFound()` 가 200 이 되는 것과 같은 원인). 로그아웃 상태로 주소를 치면 **가려던 곳도
아닌 홈 골격이 1초** 보인다. 프록시에서 끊으면 307 하나로 끝난다.

**진입점도 함께 숨긴다.** 로그인하지 않은 사람에게 늘 보이는 자리(탭바 · 홈/탐색/조건
검색 제호 버튼)에 대시보드를 두면 누를 때마다 로그인으로 튕기는 미끼가 된다. 그 넷은
숨기고, 로그인은 바로 옆 `AccountMenu` 가 안내한다. 콘텐츠 링크(`FindBand` 타일 ·
404 안내)는 남긴다 — 항상 보이는 크롬이 아니고, 눌러서 도착한 로그인 화면이 이유를 말한다.

> **익명 사용자는 담을 수는 있어도 볼 수 없다.** `WatchToggle` 은 익명 쿠키로 그대로
> 저장하고, 로그인하면 `claimAnonymousWatchlist` 가 계정으로 옮긴다 — 잃지는 않는다.
> 다만 로그인 전에는 담아 둔 것을 확인할 화면이 없다. 게이트와 합침의 산물이다.

### 이 화면만 골격이 다르다 — 앱 셸이다

나머지 화면(홈·종목 상세·탐색·로그인)은 전부 `Masthead` + 중앙 정렬 `max-w-shell` 이다.
대시보드만 다르다: 사이드바가 **뷰포트 왼쪽 끝에 붙어야** 해서 그 컨테이너 밖으로 나갔다.

| | 값 |
|---|---|
| 사이드바 | `fixed inset-y-0 left-0 z-20 w-[320px]` · `border-r-2 border-ink` · `bg-surface` |
| 본문 | `md:pl-[320px]` → 그 안에서 `mx-auto max-w-shell` |
| 상단 바 | **다른 화면과 같은 `Masthead`** — 제호가 위, 기준 시각이 그 아래, 오른쪽에 검색·테마·계정 |
| 제호 | 상단 바 안. **사이드바에는 없다** |

제호를 사이드바 머리에 뒀다가 되돌렸다(2026-08-18). 이유 둘 — 320px 에 24px 제호가
안 들어가 오른쪽 본문 위로 삐져나갔고, 무엇보다 **서비스명이 화면마다 다른 자리에 있으면
안 된다.** 사이드바는 관심 종목만 든다. 골격이 다른 것과 브랜드 자리가 다른 것은 별개다.

sticky 로 하지 않고 `fixed` 인 것이 요점이다. sticky 는 조상(그리드/컨테이너) 안에서만
붙으므로 `max-w-shell` 안에 있으면 **넓은 화면에서 사이드바 왼쪽에 여백이 남는다.**
`fixed` 는 뷰포트 기준이라 그 여백이 없다. 대신 문서 흐름에서 자리를 차지하지 않으므로
본문을 `md:pl-[320px]` 로 직접 밀어 줘야 한다 — **표 보기는 사이드바를 접으므로 밀지 않는다.**

**머리는 붙박이고 목록만 스크롤한다.** 제호·제목·버튼·그룹 탭·정렬은 `flex-none`, 목록만
`min-h-0 flex-1 overflow-y-auto overscroll-contain` 이다. 통째로 스크롤시키면 종목을
고르러 내려간 사이 그룹 탭과 정렬이 화면 밖으로 나간다. `min-h-0` 이 없으면 flex 아이템의
기본 최소 높이 때문에 목록이 사이드바를 밀어내고 스크롤이 페이지에 생긴다 — 겉보기엔
되는데 아무것도 안 붙는 상태가 된다.

시장 타일은 본문 맨 아래다. 사이드바가 `fixed` 라 **본문 어디에 두든 왼쪽은 계속 붙어
있다** — sticky 였을 때는 타일을 두 열 안에 넣어야 했지만 그 제약이 사라졌다.

모바일(<768)에는 사이드바가 없다. `WatchCard` 2단 카드 목록 + 시장 타일 + 하단 고정 액션
2개를 두고, 카드를 누르면 `/stocks/[code]` 전체 화면으로 간다.

**제목 줄이 사이드바 안에 있다** (2026-08-18). 전에는 `WatchlistHeader` 가 전체 폭에
서 있었는데, 그러면 제호(`Masthead`)의 `border-b-2` 바로 아래에 이 헤더의 `border-b-2`
가 또 놓여 **굵은 선 두 개가 12px 간격으로 쌓이고 그 사이에 28px 제목이 낀다.** 정작
화면의 본체인 종목 상세는 그 아래에서야 시작했다 — 제호를 두 번 지나야 내용이 나오는
셈이다. 지금은 오른쪽 칸이 제호 바로 아래에서 상세로 시작한다.

`WatchlistHeader` 의 `variant` 가 그 차이를 담는다 — `rail`(사이드바: h2 17px,
헤어라인, 버튼 2+1 접기) / `page`(전체 폭: h1 28px, `border-b-2`). 제목 태그가 갈리는
것은 그 옆에 종목명 `h1` 이 이미 있어서다; 한 화면에 최상위 제목이 둘이면 안 된다.

**표 보기**로 넘기면 nav 와 상세가 빠지고 전체 폭 8열 `TableHeader` + `WatchRow` 가
선다. 그때는 제목 줄이 `page` 로 돌아와 표 위에 놓인다. 컬럼 폭은 `WATCH_GRID` 상수
하나를 헤더와 데이터 행이 공유한다(어긋남 방지).

두 보기를 둔 이유: nav 폭은 340px 라 `WatchRow` 의 열 개(보유·평가손익·알림 조건까지)가
들어가지 않는다. 좁은 칸에 우겨넣어 전부 못 읽게 만드는 대신 **훑는 보기와 관리하는
보기**를 나눴다 — 합치면서 잃은 기능이 없다. 전환은 클라이언트 상태다: 공유할 가치가
없는 개인 취향이고, URL 에 실으면 상세 라우트마다 물고 다녀야 한다.

모바일(<768)은 **분할이 성립하지 않는다.** `WatchCard` 2단 카드 목록 + 시장 타일 +
하단 고정 액션 2개(`＋종목 추가` / `전체 AI 분석`)를 두고, 카드를 누르면
`/stocks/[code]` 전체 화면으로 간다. 상세 HTML 은 모바일에도 내려가지만
`hidden md:grid` 로 가려진다 — 서버는 뷰포트를 모른다.

### 6.4 왜 레이아웃이 nav 와 타일을 갖는가

선택을 쿼리스트링(`?symbol=`)으로 들면 페이지 세그먼트가 통째로 다시 돌아 **클릭마다
관심종목과 시장을 새로 조회한다** — 시장은 종목과 아무 상관 없는 데이터인데도. 게다가
목록을 들고 있는 `useWatchlistMutations` 는 `useState(initial)` 이라 새로 받은 값을
쓰지도 않는다. 버려지는 조회다.

레이아웃은 자식 간 이동에서 다시 렌더되지 않는다(Next 의 partial rendering). nav 와
타일을 거기 두면 조회도, 클라이언트 상태(그룹·정렬·선택·**돌고 있는 일괄 AI 분석**)도
그대로 살아 있고 `children`(상세)만 교체된다.

레이아웃이 직접 `await` 하지는 않는다. 그러면 제호까지 막히고, 그때 대신 나오는 것은
루트 `loading.tsx`(**홈 골격**)이라 화면이 틀린다. 목록과 시장은 서로를 기다릴 이유도
없어 `<Suspense>` 를 각자 둔다 — 목록이 먼저 오면 nav 부터 뜬다.

### 6.5 nav 행 (`WatchRowCompact`)

3줄이다. 1줄 종목명 + 현재가, 2줄 심볼·그룹 + 스파크라인 52×16 + 등락률, 3줄 AI 판단.
체크박스(순서 편집 시 드래그 핸들)는 링크 **밖**에 두어 선택과 이동이 서로를 먹지 않는다.

활성(오른쪽에 떠 있음)은 왼쪽 2px 잉크 선 + 굵은 종목명, 선택(체크)은 바탕색이다 —
둘은 동시에 참일 수 있으므로 다른 신호를 쓴다. 활성 판정은 `usePathname()` 에서 읽는다:
레이아웃은 자식의 `params` 를 볼 수 없고, `/dashboard`(코드 없음)는 페이지가 맨 위 종목을
그리므로 nav 도 같은 값을 골라야 화면과 맞는다.

### 6.6 행 구성 (`WatchRow` — 표 보기)

| 셀 | 내용 |
|---|---|
| 26px | 선택 체크박스. **순서 편집 모드**에서는 드래그 핸들로 교체 |
| 종목 | 종목명(상세 링크) + 그룹 배지 / 심볼 · 영문명 |
| 현재가 | 해외는 `$` + 소수 2자리, 국내는 원화 포맷 |
| 등락률 | `Delta` 컴포넌트가 색·부호를 단독 소유 |
| 3개월 | `Sparkline` 104×28 |
| 보유·평단 | 수량 · 평단 + 평가손익률. 보유가 없으면 "관심만" (대시로 채우지 않는다) |
| 알림 | `AlertToggle`(pill) + `AlertCondition`(자유 텍스트) |
| AI 판단 | `VerdictCell` — 진행 단계 / 판단 문구 / 오류 |

### 6.7 상호작용

| 조작 | 동작 | 제약 |
|---|---|---|
| 그룹 탭 | 클라이언트 필터 | — |
| 정렬 | 직접 정렬 · 등락률 · 종목명 · 평가손익 | — |
| 순서 변경 | `@dnd-kit` 드래그 (포인터 4px 임계 · 키보드 센서) | **`순서 편집` + `직접 정렬`** 둘 다일 때만 핸들이 뜬다 |
| 선택 → AI 분석 | 선택 종목만 SSE 스트림 | 동시 3개까지 (`MAX_CONCURRENT`) |
| 전체 AI 분석 | 현재 보이는 목록 전체 | 〃 |
| 삭제 | 로컬 상태에서 제거 | 저장소 없음 |
| 그룹 이동 · 알림 일괄 | 안내 문구만 표시 | 백엔드 저장소 필요 |

정렬이 걸린 상태에서 순서 편집을 켜면 "정렬이 걸려 있는 동안에는 순서를 바꿀 수
없습니다" 안내가 뜬다 — 화면 순서와 저장 순서가 달라 의도치 않은 재배치가 되기 때문이다.

일괄 분석은 전체 진행률이 아니라 **행마다 자기 단계**를 보여준다. 종목당 LLM 4회라
오래 걸리고, 먼저 끝난 종목부터 판단이 뜨는 편이 낫다.

| 상태 폴링 | `GET /api/stocks/listed-companies` 2초 간격, `ready` 가 되면 중단(이후 5분 staleTime) |
| 204 응답 | 배너를 숨길 뿐 검색은 정상 동작 |

### 7.5 상태

| 상태 | 화면 |

## 8. O-02 · AI 종합 판단 드로어

[AdviceDrawer.tsx](../src/features/stock/advice/components/AdviceDrawer.tsx) · 클라이언트 · S-02 와 S-03 이 **같은 인스턴스**를 공유한다

두 뷰가 동시에 렌더돼 있으므로 드로어를 각 뷰 안에 두면 SSE 스트림이 둘로 갈라진다.
그래서 `fixed` 로 컨테이너 밖에 하나만 둔다.

### 8.1 레이아웃

```
                            ┌──────────────────────────────┐
                            │ AI 종합 판단              ✕ │
                            │ 3 AGENTS → 1 DECISION        │
                            ├──────────────────────────────┤
                            │ 3개 에이전트 의견 생성 · 3/4 ◌│  AdviceProgress
                            │ ▓▓▓▓▓▓▓▓▓▓▓░░░░░  (3px)      │
                            ├──────────────────────────────┤
                            │ AI 분석은 시간이 걸립니다     │
                            │ ┌ 01 AI 저널리스트 Journalist┐│  AgentCard ×3
                            │ │  요약 3문장               ││  (도착 순)
                            │ └───────────────────────────┘│
                            │ ┌ 스켈레톤 (판단 도착 전) ──┐│
                            │ ┌ FINAL DECISION ──────────┐│  반전 배경
                            │ │ 매수 가능 34px  신뢰도 76%││
                            │ │ ▮▮▮▮▮ ▯ ▯   (5칸 미터)   ││
                            │ │ 답변 (serif 13.5/1.75)    ││
                            │ │ ＋ 매수 조건 / － 리스크   ││
                            │ └───────────────────────────┘│
                            └──────────────────────────────┘
                              데스크탑 우측 438px · 모바일 전체화면 시트
```

### 8.2 진행 표시

`stage` 는 '끝난 단계 수'이고 라벨은 '지금 하는 단계'를 말한다 → `stage + 1` 을 읽는다.

| stage | 라벨 |
|---:|---|
| 1 | 주가 데이터 조회 · 1/4 단계 |
| 2 | 뉴스·리포트 수집 · 2/4 단계 |
| 3 | 3개 에이전트 의견 생성 · 3/4 단계 |
| 4 | 최종 판단 종합 · 4/4 단계 → 완료 시 "분석 완료 · 4/4 단계" |

진행은 되감기지 않는다 — 에러 이벤트는 `stage: 0` 으로 오는데 그대로 반영하면
3/4 까지 찬 바가 0 으로 튄다 (`Math.max` 로 고정).

에이전트 카드 3장이 다 차도 최종 판단 LLM 호출이 남아 있으므로, **판단이 도착할
때까지** 스켈레톤이 자리를 지킨다.

### 8.3 구성 요소

| 요소 | 내용 |
|---|---|
| `AgentCard` | 순번 `01` · 에이전트명 · 영문 부제 · 요약. `status==="fallback"` 이면 "실패" 배지 |
| 성향 배지 | `stance`(긍정·중립·부정). LLM 구조화 출력에서 오며 폴백 의견에는 없다 |
| 근거 목록 | `sources[]` — RAG 로 검색·인용된 문서 제목(+출처). URL 이 있으면 새 탭 링크 |
| `FinalDecision` | 판단 라벨 34px · 신뢰도(5칸, 20%p 단위) · 답변 · ＋매수조건/－리스크 · 면책 |
| 규칙 기반 배지 | `source === "fallback"` 일 때 점선 테두리 + "규칙 기반 판단" + 재시도 버튼 + `fallback_decision` 캡션 |
| 오류 블록 | 판단 없이 에러만 온 경우 "AI 분석을 불러오지 못했습니다" + 재시도 |

### 8.4 데이터 흐름

```
드로어 open ──▶ useAiAdvice ──▶ POST /api/stocks/advice  (BFF)
                                       │
                                       └▶ POST /stocks/advice/stream (FastAPI SSE)
                                          snake_case → camelCase 변환 후 재방출
```

- `enabled`(=열림)가 true 가 되는 순간 1회 실행, 닫으면 `AbortController` 로 중단
- 재시도는 `attempt` 카운터를 올려 같은 스트림을 새로 연다
- BFF 가 스트림을 열기도 전에 실패하면 `stage: 0` 이벤트 하나를 만들어 보낸다 —
  드로어가 항상 에러 상태를 그릴 수 있다
- AI 타임아웃은 별도 값(`STOCK_AI_TIMEOUT_MS`, 기본 300초)

### 8.5 진입점

| 위치 | variant | 표시 |
|---|---|---|
| S-02 마스트헤드 (≥768) | `editorial` | `● AI 판단 열기/닫기` (잉크 배경) |
| S-03 상단 바 (≥768) | `console` | `RUN AI ⏎` (앰버) |
| 모바일 (<768) | `bar` | 하단 고정 `● AI 판단 열기`. 시트가 열리면 내려간다 |
| 검색 팔레트 | ⌥⏎ | `?ai=1` 로 이동 |
| 홈 브리핑 | 링크 | `/stocks/{code}?ai=1` |

모바일 탭바의 AI 탭은 **비활성**이다 — 종목 컨텍스트가 있어야 열 수 있으므로
"AI 판단은 종목 상세에서 열 수 있습니다" 안내만 한다.

## 10. 데이터 흐름

### 10.1 경로

```
서버 컴포넌트 ──▶ features/*/services ──▶ lib/api ──▶ FastAPI (/api/v1)
                                                        ▲
브라우저(클라이언트) ──▶ app/api/* (BFF) ───────────────┘
```

**브라우저는 FastAPI 를 직접 호출하지 않는다.** 백엔드 주소·키를 노출하지 않기 위해

접두사 없이 서버 전용이다.

| 소비자 | 경로 | 대상 |
|---|---|---|
| S-01 지수 | 서버 | `GET /markets/overview?category=home` |
| S-02 주가 | 서버 | `GET /stocks/history?symbol&limit=504&include_content=false` |

### 10.2 캐시

| 대상 | 주기 | 근거 |

의존하지 않는다. 공휴일 캘린더는 두지 않는다.

`USE_MOCK=1` 이면 서비스가 `features/*/model/mock.ts` 를 반환하고, AI BFF 는 고정

## 12. 미구현 · 백엔드 확장 필요

화면은 있으나 실데이터가 없는 항목이다. 전부 코드 주석에 근거가 남아 있다.

> **로그인은 더 이상 미구현이 아니다.** 구글 로그인과 이메일·비밀번호가 붙어 있고(`auth.ts` — 환경

## 14. 인증 — 로그인 수단과 세션

### 14.1 화면

| 화면 | 경로 | 열리는 조건 |
|---|---|---|
| 로그인 | `/login` | 항상 |
| 회원가입 | `/signup` | **개발자 모드에서만** (아니면 404) |
| 이메일 인증 | `/verify?email=&token=` | 〃 |
| 계정 발급 | `/admin/users` 안의 '계정 발급' | 관리자 |

### 14.2 로그인 수단 둘

설정된 것만 그린다 — 누르면 깨지는 버튼을 두지 않는다.

| 수단 | 켜지는 조건 | 비고 |
|---|---|---|
| **이메일 + 비밀번호** | DB 주소가 있으면 | 첫 자리. 해시가 `users.password_hash` 에 산다 |
| 구글 | `AUTH_GOOGLE_ID`·`AUTH_GOOGLE_SECRET` | 같은 이메일이면 한 계정(`users_email_key`) |

이메일 매직링크(Nodemailer 프로바이더)는 **2026-08-18 에 걷어냈다.** 비밀번호 로그인이
생기면서 같은 성격의 입구가 셋이 됐고, 그중 "비밀번호 없이 메일로" 가 가장 덜 쓰였다.

`nodemailer` 패키지와 `EMAIL_SERVER`·`EMAIL_FROM` 은 **남아 있다** — 개발자 모드
회원가입의 인증 메일을 그것으로 보낸다(14.5). 용도만 로그인에서 가입 인증으로 옮겨 갔고,
비워 두어도 로그인은 멀쩡하다.

**실패 문구는 하나다** — "이메일 또는 비밀번호가 올바르지 않습니다". 없는 계정과 틀린
비밀번호를 구분해 주면 어떤 이메일이 가입돼 있는지 알려주는 것이 된다. 계정을 못
찾았을 때도 `burnPasswordTime` 으로 **같은 시간**을 쓴다 — 문구로 안 알려주면서 응답
시간으로 알려주면 소용이 없다.

### 14.3 세션은 이제 JWT 다 — 고른 것이 아니라 강제된 것

원래는 DB 세션(`sessions` 테이블)이었다. Auth.js 의 Credentials 프로바이더가
"can only be used if JSON Web Tokens are enabled for sessions" 라고 명시한다.

| | 전 | 후 |
|---|---|---|
| 브라우저 | 불투명 토큰 | **서명된 JWT** (쿠키 이름은 그대로 `authjs.session-token`) |
| 서버 | `sessions` 행 | 없음 — 테이블은 남아 있지만 쓰이지 않는다 |
| 즉시 로그아웃 | 행을 지우면 끝 | **불가능.** 쿠키를 지울 뿐, 복사된 토큰은 만료(30일)까지 유효 |
| 권한(`role`) | 매 요청 DB | 매 요청 DB — `jwt` 콜백이 다시 읽는다 |

`role` 을 토큰에 굳히지 않은 이유: 관리자를 강등해도 그 사람의 토큰이 만료될 때까지
관리자로 남는다. 권한은 그렇게 오래 틀려 있어도 되는 값이 아니다. 조회 횟수는 DB
세션일 때와 같다(그때도 매 요청 `sessions`+`users` 를 읽었다).

계정이 지워졌으면 `jwt` 콜백이 `null` 을 돌려준다 — JWT 라 서버가 세션을 지울 수
없으므로, **남은 쿠키를 무효로 만드는 유일한 자리**다.

사용자·계정 행은 그대로 저장된다. 어댑터가 있으면 `createUser`·`linkAccount` 는 전략과
무관하게 돈다(`handle-login.js` 실측) — 구글 로그인이 계속 같은 계정을 만든다.

### 14.4 비밀번호 저장

`node:crypto` 의 **scrypt**. 라이브러리를 더하지 않았다 — bcrypt·argon2 는 네이티브
빌드가 필요하고, scrypt 는 Node 에 들어 있으면서 OWASP 가 나란히 권장한다.

```
users.password_hash = scrypt$N=65536,r=8,p=1$<salt base64url>$<hash base64url>
```

파라미터를 값 안에 적는다 — 비용을 나중에 올려도 **옛 해시가 그대로 검증된다.**
상수로만 두면 값을 올리는 순간 기존 사용자가 전부 못 들어온다.

컬럼은 nullable 이다. 구글로 만들어진 계정은 비밀번호가 **없고**, 그 상태로
비밀번호 로그인을 시도하면 시간만 쓰고 거절한다.

최소 길이 12자. 대문자·특수문자를 강제하지 않는 것은 NIST SP 800-63B 가 그 규칙을
권장하지 않기 때문이다 — 사용자가 예측 가능한 변형을 만들 뿐이고 길이가 훨씬 크게
기여한다.

### 14.5 계정은 관리자가 만든다

공개 가입은 **개발자 모드에서만** 열린다(`SIGNUP_ENABLED = NODE_ENV === "development"`).
환경변수 스위치가 아니라 `NODE_ENV` 인 이유는 배포에서 실수로 켜지지 않게 하기 위해서다 —
`next build` 산출물은 어떤 설정으로도 이 조건이 참이 되지 않는다.

가드는 화면과 서버 액션에 **각각** 있다. 브라우저는 액션 ID 로 직접 POST 할 수 있고
그때 페이지 컴포넌트는 실행되지 않는다 (`admin/_actions.ts` 가 `requireAdmin()` 을 두 번
부르는 것과 같은 이유).

| 경로 | `emailVerified` | 이유 |
|---|---|---|
| 관리자 발급 | 만들 때 채운다 | 관리자가 이미 그 사람을 안다. 메일이 안 가면 계정이 영영 잠긴다 |
| 공개 가입(개발자 모드) | 인증 링크를 열어야 채워진다 | 그전에는 `authorize` 가 거절한다 |

관리자 발급은 임시 비밀번호를 **한 번만** 보여준다 — 해시만 저장하므로 그 화면을
벗어나면 관리자도 복구할 수 없다.

### 14.6 아직 없는 것

비밀번호 변경·재설정 화면 · 로그인 실패 레이트 리밋 · 계정 잠금 · 유출 비밀번호 대조.
Auth.js 문서가 크리덴셜 방식을 권하지 않는 이유로 든 것들이고, 지금 그중 어느 것도
없다. 공개 가입을 열기 전에 채워야 할 목록이다.

영역과 재미 영역을 시각적으로 섞지 않는다는 요구를 **사용자가 제품에서 처음 보는
화면에서** 먼저 지킨다.

**조회를 하나도 하지 않는다.** 링크 둘을 그리는 것이 전부라 `revalidate` 를 적을
이유가 없다 — 다른 화면이 `revalidate = 0` 을 붙이는 이유(빌드 시 백엔드 접속)가
여기서는 발생하지 않는다. 유일한 동적 요인은 제호의 `AccountMenu`(세션)다.

### 15.2 S-04 · 투자 성향 온보딩 (`/saju`)

[page.tsx](../src/app/(saju)/saju/page.tsx) · 서버 컴포넌트 · `revalidate = 0` ·
셸은 [(saju)/layout.tsx](../src/app/(saju)/layout.tsx)

**사주가 이 제품에서 하는 일이 여기 전부다.** 사주는 "이 종목이 오를까"가 아니라
"당신은 어떤 투자자인가"에만 답한다. 여기서 만든 숫자 6개가 종목 판단의 개인 축이
되고, 사주 원문은 이 화면 밖으로 나가지 않는다.

| 요소 | 구현 |
|---|---|
| 제호 | `Masthead home="/saju"` + `AccountMenu` |
| 머리글 | h1 "당신은 어떤 투자자입니까" + 설명 2줄. **두 번째 줄이 "사주로 종목을 추천하지 않습니다"** — 이 문장이 없으면 화면 전체가 "사주로 주식을 고른다"로 읽힌다 |
| 본문 | `SajuOnboarding` — 흐름 전체를 `features/saju` 가 소유한다. 페이지는 출생지 목록만 서버에서 받아 넘긴다 |
| 하단 바 | `ServiceBar` (레이아웃) — **주식 탭바가 아니다** (2.1) |
| 푸터 | `Footer service="saju"` (레이아웃) — 시세 면책이 아니라 사주 고지 |

데이터 흐름: `생년월일시 → /api/saju/chart(초안) → 사용자 보정 → /api/profile(저장)`.
**저장되는 것은 숫자 6개와 표시용 문장 하나뿐이고 생년월일시는 저장하지 않는다** —
소유자 키는 관심종목과 같은 규약(`_data/owner.ts`)이라 로그인 없이도 끝까지 돈다.

주식 서비스에서 여기로 오는 길은 `/stock` 의 `ProfileBand` 하나다. 계정 메뉴에 두면
로그인이 꺼진 환경에서 통째로 사라지고, 대시보드에 두면 이미 로그인한 사람만 본다 —
콜드스타트를 통과시키는 기능이 콜드스타트를 통과한 사람에게만 보이면 앞뒤가 맞지 않는다.
